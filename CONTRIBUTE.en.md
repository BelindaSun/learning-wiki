# How to Contribute

## Suggest a Change

Open a GitHub Issue for a correction or proposal, or submit a focused Pull Request. Explain the learning problem being solved, not only the text being added.

## Writing Standard

A useful article usually moves through:

```text
the reader's problem
→ the shortest useful model
→ an example
→ where that model breaks
→ the next connection
```

The exact headings should follow the logic of the subject.

## Teaching Principles

1. Put logic before information.
2. Understand deeply, then explain simply.
3. Use humor only when it helps understanding.
4. Introduce the problem before the technology.
5. Build a mental model before adding detail.
6. Let terminology appear when the reader needs it.
7. Start with a useful approximation and explicitly upgrade it later.
8. Prefer concepts with leverage over encyclopedic completeness.

## Avoid

- opening with a wall of terminology;
- listing facts without a question chain;
- presenting an approximation as the final truth;
- repeating the same explanation across pages;
- adding sections merely to look complete.

## Links

Use ordinary relative Markdown links, not wiki-style double brackets. Check that the target exists and that category maps expose new articles.

## Review

- Read the article as a beginner.
- Verify facts and distinguish claims from inference.
- Check relative links and Markdown formatting.
- Keep Chinese and English editions structurally aligned.
- Build the website when navigation or rendering changes.

Use concise commit messages that describe the outcome. Add changelog entries for meaningful releases rather than every typo.
