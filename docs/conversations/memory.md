**业界还在用的（进阶层）：
第一个：向量数据库（Vector Database）**
普通数据库是精确查找——你搜”天气”，它找包含”天气”这个词的记录。
向量数据库是语义查找——你说”今天适合出门吗”，它能找到关于天气、心情、计划的相关记忆，即使那条记忆里根本没有”出门”这个词。
记忆层在对话中提取事实，存进按用户、会话、Agent 标识索引的向量数据库。
对 Mimo 的意义：妈妈说”我最近身体不太好”，向量数据库能在她之后问”今天吃什么好”的时候，自动联想到”她身体不好，应该推荐清淡的”——即使这两句话隔了几十条消息。
**第二个：三种温度的记忆**
这套架构把记忆分成三种温度：热记忆是当前对话窗口里的内容，零延迟但对话结束就没了；暖记忆是异步提炼出来的结构化事实，存在高速数据库里；冷记忆是长期归档，不常用但不会消失。
简单说就是：热的是工作桌，暖的是抽屉，冷的是仓库。Mimo 现在基本只有”工作桌”，没有好的”抽屉”。
**第三个：情节记忆 vs 语义记忆**
情节记忆记的是具体事件——“3月5日妈妈说她头疼”；语义记忆是从情节里提炼出来的通用知识——“妈妈有时候头疼”。两者要分开存，Agent 才能既记得细节，又能形成对一个人的整体理解。
Jupiter 的 Dreaming 做的就是这件事——把大量情节记忆，后台消化成语义记忆。

**一句话总结：**
你和 Code Claude 做的是”记笔记”，行业顶层做的是”建档案室”——不只是存，还要分类、索引、自动关联、定期整理。
对 Mimo 这个阶段来说，你们做的已经够用。等 Mimo 用户量大了、对话多了，才需要考虑向量数据库这层。

**一句话总结：** Agent 的记忆不是一个东西，是多层叠加的系统——热记忆管当下，暖记忆管近期，冷记忆管长期，设计好分工才能让 Agent 真正”记住人”。

**今天我最大的收获**
记忆的”三种温度”这个框架。热记忆是工作桌（当前对话），暖记忆是抽屉（提炼出来的摘要和事实），冷记忆是仓库（长期归档）。Mimo 的5层设计完美对应了这个框架，而且第4层”今日状态+生活线索”是 Mimo 独有的创意——让 AI 有自己的当下生活，而不只是回答问题的机器。

**原来我认为……**
记忆就是把聊天记录存起来，保留更多条就等于记忆更好。
**现在我认为……**
存聊天记录只是最基础的一层。真正好的记忆系统要做到：分层存储（热/暖/冷）、语义检索（向量数据库）、情节→语义转化（把具体事件提炼成通用知识）、以及合理的设备分工（服务器存长期，浏览器存当下）。Mimo 的5层设计已经远超大多数普通 Agent 项目。

**最重要的三个知识点**
1. **Agent 记忆的两个失忆场景**：对话中途忘记是 Context Window 满了（桌子放不下了）；跨对话忘记是没有持久化记忆系统。两个问题原因不同，解法也不同，不能混为一谈。
2. **情节记忆 vs 语义记忆**：情节记忆是具体事件（“3月5日妈妈说头疼”），语义记忆是提炼出来的通用知识（“妈妈有时候头疼”）。两者都要有，Agent 才能既记得细节又形成对人的整体理解。Jupiter 的 Dreaming 就是后台把情节记忆转化成语义记忆的过程。
3. **Mimo 的5层记忆架构**：第1层聊天记录（热记忆）→ 第2层AI摘要（情节转语义）→ 第3层家庭事实库（长期语义）→ 第4层今日状态（AI的当下生活，Mimo独创）→ 第5层运行时权重记忆（浏览器存储，跨设备会丢但设计合理）。五层各司其职，buildPrompt() 把全部揉进系统提示词再调用模型。
