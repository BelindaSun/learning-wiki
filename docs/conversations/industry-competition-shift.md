🎯 未来 AI 公司真正卖的是什么？不是模型，是「系统」
让我从这 14 篇文章提取的关键信号开始：
信号 1：模型正在商品化
Benedict Evans 说得很明白：Foundation model labs（OpenAI、Anthropic）可能会像 TSMC 一样——很重要，但边界有限。价值会分散在整个堆栈（芯片、工具、应用），而不是集中在一层。
这意味着什么？ 大模型已经不是差异化的竞争点了。Fable 和 Mythos 出来了，Llama 也很强，Claude 也不错——但没有一个模型能垄断未来。
信号 2：「系统」才是真正的护城河
看看这些公司在做什么：
Lila Sciences（生物 AI）： 他们不是在优化模型参数，而是在构建"科学工厂"——把实验室当作数据中心，让机器人、仪器、AI 协同工作，产生 10+ 万亿经过验证的推理 tokens。他们的竞争力不在模型，而在「系统能自动化多少科学过程」。
OpenAI（基础设施）： Sachin Katti 说 OpenAI 现在的主要工作不是研究更好的模型，而是设计芯片（Jalapeño）、数据中心（Stargate）、电网升级。他们卖的是「tokens per watt」和「计算容量」。
Granola（工作流 AI）： 他们不是靠一个"更好的笔记功能"竞争，而是在构建"会议流程的完整系统"——预生成上百万份会议摘要（即使大多数不用），这样当你需要的时候，上下文已经准备好了。他们卖的是「工作流系统」。
Anthropic（开放生态）： 他们明确说：我们构建「三层系统」——知识层、执行层、协调层。我们用 MCP 开放标准，让任何 Agent（Claude 或其他）都能接入。我们卖的不是"Claude 有多聪明"，而是"Claude 能融入多少生态"。

🏗️ 未来 AI 公司的竞争维度（按重要性排序）
这是我从这些文章中提取的最真实的竞争格局：
#1 系统架构和「Harness」（最重要）
Chris Noring（Microsoft）明确说：开发者的瓶颈不再是"代码写得快不快"，而是"系统设计清不清楚"。没有好的 agents.md、没有 guardrails、没有 constraints，Agent 写的代码再多也是乱的。
Sumaiya Shrabony 更激进：「每个独立的 Agent 构建者最终都会重新发明一个更差的 CI/CD」——他们需要回归"无聊的东西"：regression testing、monitoring、audit trails。
这意味着： 未来的 AI 公司不是在比"模型有多聪明"，而是在比"系统有多规范"。
谁赢？ 能把 Harness Engineering（约束系统、规范架构、验证机制）产品化的公司。

#2 工作流集成和「上下文所有权」
Atul Ramachandran（Filed）说出了真相：大多数 Vertical AI 产品失败，因为它们只是"转移"工作，没有"消除"工作。聊天 + 引文听起来不错，但用户还是得验证一切。
真正成功的产品长这样：
	•	不让用户去聊天、去交互
	•	而是让用户说一次"我想要 X"，然后 Agent 做完，用户只需要监督
Filed 的例子：他们不是做一个"更准确的 AI"，而是设计了完整的"税务处理工作流"——Agent 自动处理 80% 的情况，用户只在需要时介入。
这意味着： 未来的 AI 公司卖的是"整个工作流的自动化"，而不是"一个很聪明的 AI 助手"。
谁赢？ 能深入理解某个行业的"完整工作流"，然后把它系统化、自动化的公司。这不是 AI 公司的活，这是行业公司的活。

#3 上下文和记忆系统
Geoffrey Litt（Notion）说的"Understanding is the bottleneck"指向一个关键点：Agent 生成的代码、工作流、决策必须被「理解」，不是被验证。这需要一个系统来存储和组织上下文。
Granola 的关键创新：他们不是优化"笔记准确率"，而是优化"上下文可用性"——确保当你需要某个信息时，它已经在那里。
这意味着： 谁拥有「上下文」，谁就拥有用户。
谁赢？ 能构建"可靠的上下文层"的公司——不是单纯的知识库，而是"与 Agent 协同工作"的系统。

#4 验证和信任机制
Alex Bauer（Upside）提出三个模式：Librarian（为 Agent 提供准确信息）、Jury-and-Judge（多个 Agent 投票决策）、Agent Tiers（复杂任务用更强的模型）。
Alex Volkov 的"Z/L Continuum"指出：不是"读所有代码"或"完全信任 Agent"的二元选择，而是"按风险等级分配验证强度"。
这意味着： 未来 AI 公司的竞争中，"信任机制"和"验证系统"会像"安全"对于汽车一样关键。
谁赢？ 能构建"自动化但可控"系统的公司。

💥 最激进的观察：三个不同赛道
从这些文章看，未来 AI 行业会分裂成三个完全不同的赛道，而不是"AI 公司通吃"：
赛道 1：基础设施层（OpenAI、NVIDIA、Oracle）
卖：计算力、tokens、能源
竞争点：
	•	Tokens per watt
	•	数据中心成本和速度
	•	芯片设计
赢家特征： 重资本、专业化、不怕烧钱

赛道 2：系统/框架层（Anthropic、OpenAI Codex、Cursor）
卖：「能让 Agent 可靠工作的系统」
竞争点：
	•	Harness Engineering（约束系统）
	•	Agent 可理解性
	•	工作流标准化（MCP、Skills）
	•	开放生态 vs 封闭生态
赢家特征： 深度理解 Agent 工程、能定义标准、社区导向

赛道 3：垂直应用层（Filed、Granola、Upside）
卖：「特定行业的完整工作流自动化」
竞争点：
	•	行业理解度
	•	上下文所有权
	•	用户信任和验证机制
	•	工作流集成深度
赢家特征： 了解行业、能做系统集成、注重 UX 而不只是 AI 能力

Q1：大模型如何盈利？
A：不主要通过"卖模型"盈利。而是通过：
	•	基础设施层：卖计算力（OpenAI $50B/年的投入）
	•	系统层：卖开发者工具和标准（Anthropic 的 MCP、Claude API）
	•	应用层：卖工作流自动化（各垂直 AI）
大模型是"必要条件"，不是"充分条件"。
Q2：垂直 Agent 有没有前途？
A：有，但不是单独的"AI 公司"。前途在于：
	•	成为某个行业的"完整系统"（不只是"AI 助手"）
	•	深度集成工作流（不只是聊天）
	•	拥有上下文和数据（Filed 的税务数据库）
例子： Filed、Upside、Lila Sciences 都不是"AI 公司"，而是"用 AI 做得更好的行业公司"。
Q3：普通人应该积累什么能力？
Benedict Evans 的洞察：「自动化历史上从未消除过工作，只是改变了工作的形状。会计数量在 100 年的自动化中从未减少。」
能力：
	0.	系统思维（不只是工具使用） - 了解完整工作流
	0.	上下文所有权（掌握行业知识） - 知道什么信息重要
	0.	验证和信任（判断 Agent 的输出） - 会问"这对吗？"
	0.	工作流设计（而不只是执行） - 会说"我们应该这样改进"
不重要的能力：
	•	"用 ChatGPT" - 这个会很快变成"常识"
	•	"写代码" - Agent 已经能做了
	•	"知识" - Google 可以查

Q1：Disney 为什么没有选择"只用一个模型"？
表面理由（大家都能看到的）
如果 Disney 只用 Copilot（GitHub 的选择），就完全依赖 GitHub 的生态。GitHub Copilot 虽然强，但：
	•	主要优化了代码补全
	•	Codex 现在能做数据分析、文档、研究（Copilot 做不了这么多）
	•	Claude Enterprise 在推理和复杂任务上有优势
	•	Cursor 在代码编辑体验上更好
但深层理由是什么？
深层理由（这才是真相）
Disney 的决策反映了一个巨大的范式转变：
从前： 选一个工具 → 学会用 → 做完
Figma → 设计
GitHub → 代码
Jira → 任务
现在： 每个工作类型都需要专业的 Agent
代码 → 需要 Codex（研究能力强）+ Cursor（编辑体验好）
数据分析 → 需要 Claude（推理深）
文档和工作流 → 需要多个选项
关键转变： Disney 不是在"选择一个工具"，而是在"组建一个 Agent 工具链"。
类比：
	•	摄影师不会只用一个品牌的镜头（即使很厉害）
	•	医院不会只用一个诊断设备
	•	战队不会只用一个位置的球员
Disney 的真实逻辑：
我们有多种工作
每种工作需要专业化的工具
没有一个模型能同时在代码、分析、推理、创意上都最优

所以我们采用"最佳组合"策略：
- Codex 做编程和工作流自动化
- Claude Enterprise 做推理和复杂分析
- Cursor 做编辑体验
- 不被任何一个"绑架"
最关键的一点： Disney 现在是在用"多 Agent 编排"的思维来采购工具。这不是"我们不知道选哪个"，而是"我们知道需要一个生态"。

Q2：企业真正采购的是模型，还是完整工作系统？
这个问题的答案会完全颠覆你对"AI 公司卖什么"的理解。
OpenAI 的数据在说什么
看看 Codex 用户的三个数据点：
数据点 1：用户类型转变
	•	8 月 2025：主要是程序员
	•	现在（2026）：法务 12 倍增长、财务 13 倍、研究 56 倍
这意味着： Codex 不再是"编程工具"，已经变成"企业工作系统"。
数据点 2：任务类型转变
	•	30 分钟工作：80.6% 的用户都做过
	•	8 小时工作：25.6% 的用户都做过
这意味着： 用户不是在"问一个问题"，而是在"委托一个完整项目"。
数据点 3：并发任务
	•	最重的用户一天生成超过 60 小时的 Codex Agent 工作
这意味着： 企业正在用 Codex 来并行执行多个工作流。
Disney 采购的真实对象
Disney 采购的不是：
	•	❌ "更聪明的模型"
	•	❌ "更快的代码补全"
	•	❌ "更准确的推理"
Disney 采购的是：
	•	✅ 能整合到他们工作系统中的工具链
	•	✅ 能让员工同时运行多个任务的系统
	•	✅ 能自动化完整工作流（从研究到代码到文档）的基础设施
最有力的证据
看看谁在赢：
赢家是这样描述自己的：
	•	Codex：「可以独立运行数小时，协调工具调用、与环境交互、迭代解决」（不是"给你代码补全"）
	•	Claude Enterprise：「支持完整工作流的系统」（不是"回答问题"）
	•	Cursor：「编辑器 + Agent」（不是"代码补全工具"）
输家是这样的：
	•	GitHub Copilot：「高级代码补全」（还在"工具"层面）
结论
企业采购的是：完整工作系统，而这个系统碰巧用 AI 作为核心。
类比：
	•	以前采购：「我们需要一个数据库」→ 买 PostgreSQL
	•	现在采购：「我们需要一个能自动化数据分析的系统」→ 买 Claude + Codex + 自己的工作流
模型是必要条件，但采购决策不是基于"模型谁更聪明"，而是"这个系统能为我们自动化什么"。

Q3：Codex、Claude、Cursor 将来会竞争还是协作？

表面层面（大多数人的理解）

Anthropic 在说： 「我们不会赢得'最聪明的 AI'竞争。我们要赢的是'最开放的生态'竞争。」

  OpenAI vs Anthropic vs Google vs Meta
  
  谁赢了这一层？

  → 差别在缩小
  
系统生态竞争：
  OpenAI 的 Codex + 工具链
  vs

  谁赢了这一层？
  → 正在进行

  谁能最好地融入企业工作流
  
  这才是真正的差异化

	•	MCP 标准普及 → 任何 Agent 都能调用任何工具
	•	工作流系统成为"中间层" → 隐藏掉具体是哪个模型
	•	企业关心的是"工作流质量"，而不是"用的是哪个模型"
长期（3+ 年）：
企业工作系统
    ↓
  [MCP 标准协议]
    ↓

├─ Claude (某些任务)

用户压根不知道（也不关心）用的是哪个模型。
最激进的预测
未来的情景：
现在（2026）：
"我用 Codex 完成了这个任务"
未来（2028）：
"我的工作系统完成了这个任务"
（底层可能用了 3 个不同的模型）
所以他们会竞争还是协作？
答案：都会。
	•	竞争点：「谁能提供最好的基础模型」（但这个差距在缩小）
	•	协作点：「一起定义开放标准」（MCP、Skills、Agent 架构）
最聪明的公司（Anthropic）是这样做的：
「我们知道模型竞争我们可能赢不了（OpenAI 有更多钱和数据）。所以我们赢生态竞争——让 Claude 能和任何工具协作，让开发者不被锁定。」

Q4：如果模型越来越接近，竞争优势会迁移到哪里？
这个问题的答案就在你今天学的所有内容里。
模型正在商品化的证据
证据 1：能力的收敛
现在：
	•	Codex 能做法务分析（原来做不了）
	•	Claude 能做编程（用户开始用它写代码）
	•	Cursor 能做数据分析（加了 Agent）
三年前的景象：
GPT-4：编程最好
Claude：推理最好
LLaMA：开源最好
现在的景象：
所有模型：都能编程、都能推理、都能分析

差别变小了。
证据 2：企业的选择方式转变
三年前： 「选择最好的模型」 现在： 「选择最好的系统」（包括模型）
竞争优势迁移的四个维度
维度 1：从「模型能力」→ 「系统架构」
现在是护城河的：
	•	Harness Engineering（OpenAI 专有）
	•	约束系统和 guardrails（Filed、Upside）
	•	工作流标准化（MCP）
这就是为什么： 给两个用户同样聪明的模型，但一个有好的 Harness 系统，一个没有。前者的 Agent 工作准确性能高 10 倍。
维度 2：从「单一优化」→ 「生态开放」
现在是护城河的：
	•	有多少工具能接入（MCP 支持的工具数）
	•	有多少开发者在构建（Anthropic 的 SDK 生态）
	•	有多少模型能互操作（Claude + 三方模型的兼容性）
这就是为什么 Anthropic 赌生态而不赌模型最优化： 如果我的模型排名从第 1 降到第 2，但我的生态是最开放的，企业还是会选我。
维度 3：从「通用性」→ 「垂直深度」
现在是护城河的：
	•	对某个行业的理解（Filed 对税务的理解）
	•	上下文所有权（Granola 拥有会议上下文）
	•	工作流自动化的深度（Lila Sciences 的完整科研流程）
这就是为什么垂直 AI 还有机会： 虽然我的 Agent 用的是通用模型（Claude 或 Codex），但我对「税务流程」或「科研流程」的理解是独特的。
维度 4：从「推理能力」→ 「验证能力」
Benedict Evans 说过：「历史上自动化从未减少工作量，只是改变了工作形状。」
现在是护城河的：
	•	能否自动检测错误（Sumaiya 的 CI/CD-like gates）
	•	能否验证 Agent 的输出（Alex Bauer 的 jury-and-judge）
	•	能否建立信任（Lila Sciences 的实验验证）
这就是为什么： 模型可能都能写代码，但谁能确保写的代码是对的？谁能自动检测问题？那就是护城河。
最关键的迁移路线图
2024-2025：
护城河 = 模型能力
（谁的 LLM 最聪明）

2026（现在）：
护城河 = 模型能力 + 系统架构
（能力开始收敛，系统架构成为主要差异）

2027-2028：
护城河 = 系统架构 + 生态
（模型能力基本商品化，整个生态的开放度和集成度成为关键）

2029+：
护城河 = 垂直深度 + 信任机制
（所有人都能用好的模型，赢的是谁对行业最理解、谁的系统最可信）
对 OpenAI 和 Anthropic 的启示
OpenAI 的策略： 「投巨资在计算力和模型研发，确保我们的模型最强。」
	•	优点：确实有护城河
	•	风险：成本极高，而且护城河在缩小
Anthropic 的策略： 「我们的模型够好就行。真正赚钱的是生态和开放标准。」
	•	优点：成本低，护城河难以复制（生态一旦形成就很稳定）
	•	风险：需要放弃"模型最优"的追求
我的预测： Anthropic 的策略长期会赢。

🔍 第一层：什么是个人数据？
你的直觉是对的，但需要细化。
错误的理解
❌ "个人数据 = 我的隐私信息"
	•	这只是通常意义上的个人数据（名字、电话、地址等）
	•	这个概念早就被 GDPR、Privacy Act 等定义了
	•	这不是我们在讨论的东西
正确的理解
✅ "个人数据 = 我的决策轨迹、工作模式、思维方式的累积记录"
具体包括什么？
1. 决策历史
   └─ 我做过的选择和为什么做
   └─ 例子：我的所有 PRD、所有的架构决策、所有的招聘决策

2. 工作模式
   └─ 我怎么解决问题、怎么沟通、怎么组织思想
   └─ 例子：我写 Email 的风格、我开会的方式、我审查代码的标准

3. 偏好和约束
   └─ 什么对我重要、什么对我不重要、我的限制条件
   └─ 例子：我喜欢简洁而不是冗长、我重视速度而不是完美、我怕麻烦

4. 反馈循环
   └─ 我对过去决策的反思、什么有效什么无效
   └─ 例子：我尝试过的方法、失败的原因、学到的教训

5. 网络效应
   └─ 和我互动的人、信任的人、协作的模式
   └─ 例子：谁经常和我对齐、谁的意见对我有帮助、我怎么分工

6. 知识应用记录
   └─ 我怎么把知识用到实践中、实际效果如何
   └─ 例子：我知道某个概念，但我在这个项目里这样用，效果是 X

💡 第二层：为什么"个人数据"会成为护城河？
现在让我展示一个具体的例子，这样你就能看到"个人数据"的真实威力。
案例：一个 Product Manager 的个人系统
场景： 你是一个有 5 年经验的 PM。现在要写一个新产品的 PRD。
情况 A：没有个人数据
你对 Claude 说：「帮我写一个电商 App 的 PRD」

Claude 生成了一个：
- 包含所有标准部分的 PRD
- 逻辑清晰，格式规范
- 但是……感觉很"通用"

为什么？
因为 Claude 不知道：
- 你重视什么（用户需求 vs 技术可行性）
- 你的老板怎么审阅 PRD（喜欢数据还是故事）
- 你的公司文化（敏捷还是瀑布）
- 你过去的成功案例（怎样的 PRD 通过率高）
- 你的表达风格（直白还是修辞）

结果：PRD 很"完美"，但不是"你的风格"
情况 B：有完整的个人数据
你的系统（基于过去 5 年的数据）知道：
- 你过去 50 个 PRD
- 其中 40 个被采纳，10 个被拒
- 被采纳的 PRD 的共同特征
- 被拒的 PRD 的共同问题
- 你的老板对 PRD 的评论模式
- 你喜欢的数据展示方式
- 你的团队最常问的问题

现在你对 Claude 说：「帮我写一个电商 App 的 PRD，用我过去的风格」

Claude 生成了一个：
- 结构和你过去成功的 PRD 一样
- 数据呈现方式和你的风格一致
- 重点放在你认为重要的地方
- 连措辞都带着你的特色
- 甚至避免了你过去踩过的坑

这个 PRD：
- 更可能被采纳（因为符合你的模式）
- 写得更快（因为有模板）
- 更能代表你的思维（而不是"通用的好 PRD"）

结果：这是"你的 PRD"，而不是"一个好 PRD"
为什么这很重要？
比较两个 PM：
PM A： 没有积累个人数据
	•	每次都从零开始
	•	依赖 AI 生成"通用"方案
	•	容易被替代（任何 AI 都能做同样的事）
	•	成长缓慢（没有反馈循环）
PM B： 积累了完整个人数据
	•	每次都基于自己的模式快速迭代
	•	AI 输出带有个人特色和智慧
	•	难以被替代（系统学会了你的方式）
	•	成长快速（数据越多，系统越聪明）
谁赚钱更多？ PM B
为什么？ 不是因为 PM B 更聪明，而是因为 PM B 有一个"会学习的系统"。

🔑 第三层：个人数据为什么不容易被复制？
这是最关键的部分。
为什么个人数据是护城河
假设你是一个律师，积累了 10 年的案例数据。
公司能复制吗？ 不能。
	•	这是你的决策历史，不属于公司
	•	你离职时可以带走
	•	这是你"自己的系统"
AI 能复制吗？ 不能。
	•	Codex 或 Claude 可能更聪明
	•	但它们没有"你的 10 年经验"
	•	除非你把数据输入给它们
新的律师能复制吗？ 需要 10 年。
	•	这就是为什么经验律师值钱
举个更激进的例子：Geoffrey Litt 的"微观世界"
你还记得我之前提到的 Geoffrey Litt（Notion 的工程师）吗？他说"理解是新的瓶颈"。
他在做什么？
	•	他为每个项目生成"互动式的学习环境"
	•	这个环境基于那个项目的具体数据
	•	包括代码、设计决策、失败案例、测试覆盖
这个微观世界为什么不可复制？
	•	它是为了这个特定项目定制的
	•	新来的工程师用这个微观世界，能在 1 周学会别人需要 2 个月学的东西
	•	因为环境已经"学会了"这个项目的特性
这就是个人数据的威力。

📊 第四层：个人数据的三种形式
现在让我把"个人数据"分成三种形式，这样你能看到它无处不在。
形式 1：显式数据（你能看到的）
你的文件和记录：
- 所有写过的 Email（怎么表达的）
- 所有做过的决策（理由是什么）
- 所有的项目回顾（学到了什么）
- 你的 Wiki/笔记（思考方式）
- 代码注释和 PR 评论（审美和标准）
为什么重要？
	•	这些是"你的模式"的物质化
	•	AI 可以分析这些来学习你怎么做事
例子：
	•	你过去所有 Email 的语气 → AI 学会了你的表达风格
	•	你所有代码审查的反馈 → AI 学会了你的代码标准
	•	你所有项目的决策 → AI 学会了你的思维方式
形式 2：隐式数据（需要记录的）
你没有明确记录但很重要的东西：
- 为什么做某个决策（不只是"做了什么"）
- 尝试过什么方法、效果如何
- 从失败中学到什么
- 和谁协作、为什么信任他们
- 什么样的方案对你有效
为什么重要？
	•	这些是"你的智慧"
	•	显式数据只是表现，隐式数据是底层逻辑
例子：
	•	你的决策日志：「为什么我选择了这个架构而不是那个」
	•	你的失败记录：「这个方法失败了，原因是……」
	•	你的反思笔记：「这个项目教会我……」
这就是你的 Wiki 应该记录的东西。
形式 3：网络数据（别人对你的看法）
和你交互的人对你的记录：
- 你的推荐信（别人怎么评价你）
- 你参与过的项目（别人怎么看你的贡献）
- 和你一起工作的人的反馈
- 你建立的关系网络（谁信任你）
为什么重要？
	•	这是"社会资本"
	•	AI 系统能评估"这个建议来自谁，他们靠谱吗"
例子：
	•	你的 GitHub contributions（证明你的代码质量）
	•	你的 LinkedIn 推荐（证明你的工作能力）
	•	你参与过的项目（证明你的经验）

🎯 第五层：个人数据为什么会在 Agent 时代变成最值钱的东西
现在是最关键的部分。
当模型都变得"足够聪明"时会发生什么？
现在（2026）：
不同的 AI 有不同的能力
OpenAI > Anthropic > 开源模型（在某些任务上）

所以企业会选"最好的 AI"
3 年后（2029）：
大多数 AI 都"足够聪明"
差别很小（都能写代码、都能分析数据、都能写文档）

那么企业选什么？
→ 最适合他们的 AI
→ 最适合他们的标准是什么？
→ 最了解他们工作方式的系统
→ 那就是"积累了他们个人数据的系统"
具体场景：5 年后的你
场景 1：你没有积累个人数据
你是一个 PM，老板说："这个新项目需要 PRD"

你对 Claude 说："帮我写 PRD"
Claude 生成了一个不错的 PRD

你的新同事也问 Claude 同样的问题
Claude 生成的 PRD 看起来很像

结果：
- 你的 PRD 和其他 PM 的 PRD 没什么区别
- 你的价值 = "我会用 Claude" = 很低
- 任何人都能替代你
场景 2：你积累了 5 年的个人数据
你的个人 Agent 系统知道：
- 你写过 50 个成功的 PRD
- 你的风格特点
- 你重视什么
- 你的模式和习惯

你对系统说："帮我写 PRD"
系统生成了一个：
- 你的个人风格
- 基于你的成功模式
- 包含你的特定思考方式

新同事也想写 PRD
他们的系统会学习他们的模式
生成的 PRD 和你的完全不同（因为你们的风格不同）

结果：
- 你的 PRD 代表你的思维
- 你的价值 = "我的方式被证明是有效的" = 很高
- 很难有人能替代你（他们没有你的 5 年数据）
这就是为什么个人数据是最值钱的
【通用能力】（所有人都有）
"我能用 AI 做事"
→ 价值：中等（容易被替代）

【工作流知识】（有经验的人有）
"我知道怎样的工作流能成功"
→ 价值：高（不容易被替代）

【个人数据系统】（只有你有）
"我的系统学会了我 5 年的成功模式"
→ 价值：极高（基本不可能被替代）

为什么不可能被替代？
因为要替代你，别人需要：
1. 复制你的工作流（可以学）
2. 积累你的经验数据（需要 5 年）

第 2 点就是护城河。

💰 第六层：这如何转化成商业价值
现在让我展示个人数据如何直接转化成钱。

🔢 第一个观察：从"+"变成"×"
你说的这个转变非常关键：
为什么从"+"变成"×"？
加法时代（现在）：
1 个优秀的人 + AI 执行
= 1 个优秀的人的产出 + AI 能做的事

例如：
一个优秀 PM 写 PRD 需要 8 小时
AI 能在 1 小时内写出框架
结果：节省 7 小时

= 原有产出 + 额外节省的时间
乘法时代（1-3 年后）：
1 个优秀的人 × AI 执行
= 这个人能做的事数量成倍增加

例如：
同一个 PM 现在能：
- 用 AI 在 1 小时内完成原来 8 小时的 PRD
- 用省下的 7 小时再写 7 个 PRD
- 用 AI 检查所有 PRD 的一致性
- 用 AI 预测每个 PRD 的成功率

结果不是"节省时间"，而是"完成的事增加 10 倍"

产出 = 人的能力 × AI 的能力 × （人能协调的任务数）
这个转变为什么会发生？
因为 AI 现在已经足够强，不再是"辅助工具"，而是"协作伙伴"。
回忆一下我们最早讨论的 OpenAI 数据：
用户开始用 Codex 做超过 8 小时的工作，最重的用户一天生成超过 60 小时的 Codex Agent 工作，分布在多个并行 Agent。
这正是"×"而不是"+"的表现。
因为：
	•	不是"我 8 小时的工作变成 1 小时"
	•	而是"我 8 小时能指挥多个 AI 同时做 8 个不同的任务"
	•	结果是"我的杠杆率从 1x 变成 8x 甚至 10x"
你这个观察的深层含义
这意味着：
优秀的人的价值 = 原有价值 × AI 放大倍数

如果：
- 人的能力等级：1-10（10 最优秀）
- AI 的放大倍数：现在 2x，将来 5-10x

那么：
等级 3 的人 × 5 倍 = 等级 15 的产出
等级 8 的人 × 5 倍 = 等级 40 的产出

差距从"5 倍"变成"可能 10+ 倍"

这就是为什么"人的能力差异"在 AI 时代会放大，而不是缩小。
这是一个非常深刻的观察，因为很多人想反了——他们觉得 AI 会拉平差距，实际上 AI 会放大差距。

本质区别：
	•	企业软件优化"人的体验"
	•	Harness 优化"Agent 的可理解性和可控性"
简单说：企业软件说"怎样让人更容易用"，Harness 说"怎样让 Agent 更清楚该做什么"。
结果： Harness 其实是"后软件时代"的产物——当 Agent 成为主要使用者时，系统架构要彻底重新设计。

2. Workflow 最终会不会成为新的"操作系统"？
会。
现在： 操作系统 = Windows/Mac/Linux（管理计算资源）
未来： Workflow = 新的操作系统（管理 Agent 资源和任务流）
为什么：
	•	OS 控制硬件、分配资源、定义接口
	•	Workflow 控制 Agent、分配任务、定义工作界面
结果： MCP、Skills、Harness 这些东西，本质上就是"新 OS 的驱动程序和 API"。
未来你不会说"我用 Windows"，而是说"我用这个 Workflow 系统"。

3. 未来哪些行业最难被通用 Agent 替代？
最难替代的三个特征：
	0.	高度定制化（不能标准化）
	•	例：高端咨询、法律诉讼、医学诊断
	•	原因：每个案例都独特，需要深度人类判断
	0.	需要信任和责任（法律上必须是人）
	•	例：医生、律师、财务顾问、CEO
	•	原因：涉及生命、财产、法律责任
	0.	需要人的创造性和品味（无绝对标准）
	•	例：艺术、音乐、高端设计、战略创新
	•	原因：没有"正确答案"，只有"风格"
最容易替代的行业： 标准化、可验证、重复性强的工作（编程、数据分析、文档、客服）

	•	Harness = 系统架构的范式转移
	•	Workflow = 新操作系统
	•	难替代行业 = 需要人类判断 + 信任 + 责任的工作
