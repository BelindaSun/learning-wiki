**多模态（Multimodal）是什么**
简单说：**“模态”（modality）指的是信息的呈现形式**——文字是一种模态，图像是一种模态，音频、视频、代码也各是一种模态。“多模态”就是指一个 AI 模型能同时理解和/或生成不止一种类型的信息，而不是只能处理纯文本。
早期的大语言模型（比如最早的 GPT-3）本质上是”单模态”的——只能吃文字、吐文字。多模态模型则打通了不同信息形式之间的壁垒，典型能力包括：
- **看图**：上传一张截图、照片、图表，模型能描述内容、读懂里面的文字、分析数据趋势
- **听/生成语音**：理解语音输入，或者用语音回应（比如你提到的 ChatGPT Voice、GPT-Live）
- **理解视频**：抽取视频里的关键帧或音轨来理解内容
- **生成图像**：从文字描述画出图片
- **读文档/PDF**：不只是提取文字，还能”看懂”版式、表格、图表这些视觉结构

**为什么这波多模态特别被强调**
跟纯文本模型比，多模态本质上解决了一个问题：**现实世界的信息本来就不是纯文本的**。你想让 AI 帮你看一眼产品原型截图提意见，看一段监控视频判断异常，或者听一段会议录音总结要点——这些任务光靠文字输入根本没法做。
技术实现上，主流做法是把不同模态的信息都转换成统一的”token”表示，让同一个模型能在一个统一的空间里处理文字、图像、音频这些不同类型的输入输出，而不是分别用几个独立的小模型拼凑起来（那种拼凑式的做法通常被称为”pipeline”或”级联”，效果和体验都不如原生多模态）。
**跟你之前聊的 harness/agent 有什么关系**
值得一提的是，多模态和 agent 能力是在往一起融合的——比如一个编程 agent 如果是多模态的，就能直接”看”你截的 UI 错误截图去定位 bug，而不需要你把错误信息转写成文字描述给它。这也是为什么现在几乎所有主流模型（Claude、GPT 系列、Gemini）都在往多模态方向发展，它是让 AI 真正能干”现实世界的活”的基础能力之一。

那你能给我讲讲这个多模态怎么实现的，听上去挺难的，比纯文本这类的可是难多了吧。
多模态实现的核心思路其实没有想象中那么”魔法”——本质上是想办法把不同类型的信息**都变成同一种语言**（数字向量），然后让模型用同一套”大脑”去处理。具体拆开来看：
**第一步：把每种模态”翻译”成模型能懂的东西**
纯文本模型的做法是：把文字切成一个个”token”（可以理解成词或词根片段），每个 token 对应一个数字编号，模型再把这些编号转换成一串串数字向量（embedding），在这个向量空间里做计算。
多模态模型要做的，就是把图像、音频这些也变成类似的向量表示：
- **图像**：常见做法是把一张图切成很多小方块（patch，比如 16×16 像素一块），每个小块被编码成一个向量，这样一张图就变成了”一串视觉 token”，跟文字 token 长得很像，可以塞进同一个序列里
- **音频**：把声音波形切成短时间片段，转换成频谱特征，再编码成向量序列
- **视频**：本质上是”图像 + 时间”，通常按帧采样，加上时序信息

这一步的关键突破是找到了让图像、音频”token化”的有效方法——一旦做到这一步，剩下的处理逻辑就可以复用文本模型那套成熟的 Transformer 架构了。
**第二步：让不同模态”对齐”到同一个语义空间**
光是都变成向量还不够——你还得让模型明白”一张猫的照片”和”猫”这个词说的是同一件事。这靠的是**大规模的配对训练数据**：海量的”图片+对应文字描述”、“语音+对应文字转写”这样的配对数据，训练模型把语义相近的内容（不管来自哪个模态）映射到向量空间里相近的位置。
这一步是公认最难、也最耗资源的部分——不是因为技术原理有多复杂，而是因为需要极大规模、高质量的多模态配对数据，而且训练和推理的算力成本比纯文本高出不少（一张图切完可能产生几百甚至上千个 token，比一段等量信息的文字消耗的 token 多得多）。
**第三步：统一到一个模型里处理**
早期的”多模态”其实是几个独立模型拼起来的——一个专门识图的模型 + 一个专门写文字的模型，中间靠人工或者简单规则去”翻译”衔接。现在主流的原生多模态模型，是让不同模态的 token 直接混合进同一个序列，由同一套 Transformer 网络统一处理、统一输出——这样模型才能真正做到”结合图里看到的内容和你问的文字问题一起推理”，而不是简单地”先描述图片，再回答问题”这种割裂的两步走。
**为什么比纯文本难**
你的直觉是对的，主要难在几点：
- **数据获取更贵**：高质量的图文/音频文字配对数据比纯文本语料难收集、难标注得多
- **计算量陡增**：图像、视频转成 token 序列后长度暴涨，直接推高训练和推理成本（这也是你之前问的 token 消耗问题的另一个维度）
- **模态之间的”翻译损耗”**：怎么让模型既保留图像里的细粒度视觉信息，又不让 token 序列长到爆炸，这中间的取舍到现在都还是活跃的研究方向
