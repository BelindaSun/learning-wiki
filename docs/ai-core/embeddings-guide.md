# Embeddings 完全指南

**核心概念**: [Inference 完全指南](inference-system-guide.md#第-2-步embedding变成向量) 已经讲过，模型在推理时会把每个 Token 变成一个向量，向量在高维空间里的位置代表这个词的"语义"——意思相近的词，向量也挨得近。这篇要讲的是：这个"把意思变成一串数字，然后比较数字有多接近"的想法，不只发生在模型内部的一次推理里，可以单独拿出来当工具用——这正是语义搜索、RAG、推荐系统的共同地基。

**关键洞察**: Embedding 比的不是字面有没有重复，是意思像不像。"怎么减肥"和"如何瘦身"几乎没有共同的字，但向量会挨得很近——这是它跟关键词搜索最本质的区别。

## 从"一个词的向量"到"一段话的向量"

Inference 里讲的是"每个 Token 变成一个向量"，是模型内部一次推理过程中的中间步骤。但同样的想法可以单独拿出来用：把**一整句话、一整段文字，甚至一整篇文档**，变成**一个**向量，代表这段文字"整体在说什么"。

```
"如何科学地减肥"        → [0.12, -0.45, 0.88, ...]
"怎样才能健康地瘦身"     → [0.14, -0.42, 0.85, ...]  ← 挨得很近
"今天天气怎么样"         → [-0.61, 0.33, 0.02, ...]  ← 离得很远
```

产生这种"整段文字 → 一个向量"的模型，叫 **Embedding 模型**——跟负责聊天生成回答的模型不是同一种模型，专门只做"把文字变成能比较语义的向量"这一件事。

## 怎么比较两个向量像不像

不需要懂背后的数学，记住方向就够：把每个向量想象成高维空间里的一个点，或者一个从原点出发的箭头。**两个向量指向的方向越接近，代表的意思就越接近**——这个"方向接近程度"最常见的量化方式叫**余弦相似度（Cosine Similarity）**，输出一个数字，越接近 1 代表越相似。

```
"减肥"的向量  ↗
"瘦身"的向量  ↗   ← 方向几乎一样，相似度接近 1

"减肥"的向量  ↗
"天气"的向量  →   ← 方向差很多，相似度接近 0
```

## 语义搜索 vs 关键词搜索

这是 Embedding 最直观的价值。传统的关键词搜索，靠的是字面匹配——搜"Python 教程"，找不到一篇标题是"新手怎么上手 Python"的文章，因为"教程"两个字没出现。**语义搜索**不比对字面，比对的是 Embedding 之后的向量距离：

```
关键词搜索："Python 教程"
  → 只匹配包含"教程"这两个字的文档
  → "新手怎么上手 Python" 没有"教程"二字，搜不到

语义搜索："Python 教程"
  → 先把查询变成向量
  → 在所有文档的向量里找"方向最接近"的几个
  → "新手怎么上手 Python" 的向量方向很接近，能被找到
```

这也是为什么现在很多产品的"搜索"用起来比以前聪明——很多时候背后是语义搜索在起作用，不是关键词匹配变强了。

## Embedding 能用来干什么

除了搜索，同一个"比较向量距离"的想法还能用在：

- **RAG（检索增强生成）**：先用语义搜索找到相关资料，再交给模型基于这些资料回答——具体怎么串起来，见 [RAG 完全指南](../ai-application/rag-guide.md)
- **Agent 记忆检索**：[Agent 记忆系统完全指南](memory-system-guide.md#向量数据库和语义检索) 已经讲过，同一个"比较向量"的想法，用在从记忆库里找"跟这次提问语义相关的旧记忆"上
- **推荐系统**：找"跟你之前喜欢的内容语义相近"的其他内容
- **聚类/去重**：把语义相近的一堆文本自动分组，或者找出说的是同一件事的重复内容

这些应用的共同点：都是"先把文字变成向量，再比较向量"这同一个动作的不同用法。
