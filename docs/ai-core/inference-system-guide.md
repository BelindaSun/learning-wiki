# Inference 推理系统：答案怎样一步步生成

**核心概念**: Inference 不是从资料库里取出一段现成答案，而是让输入经过模型已经学到的大量权重，算出下一个 Token 的概率，再把新 Token 放回输入继续算。看似完整的一段回答，其实是同一个预测循环高速重复的结果。

**学习来源**: Claude 直接对话学习  
**最大收获**: “一次预测下一个 Token”听起来很简单，但模型会在每一步利用上下文、词之间的关系和训练中形成的内部表示；简单的是循环形式，不是模型在循环里完成的计算。

📖 **完整学习对话记录**：[Inference](../conversations/inference.md)、[Attention（接 inference）](../conversations/attention.md)

**第一次接触这个主题？** 建议先了解：[LLM](../../glossary.md#llm) · [Token](../../glossary.md#token)

## 先拿走一张最小地图

模型收到一句话后，核心路径可以先压缩成七步：

```text
文字
  ↓ 切成模型能处理的单位
Tokens
  ↓ 变成数值表示
Vectors
  ↓ 经过多层 Transformer，结合上下文更新表示
Contextual representations
  ↓ 映射成下一个 Token 的概率
Probability distribution
  ↓ 按生成策略选择一个 Token
New token
  └──────── 放回输入，重复同一个循环 ────────┘
```

这张图是一个有用近似：它先把重点放在“输入怎样变成下一个 Token”。真实推理系统还要处理缓存、批处理、并行、内存搬运和服务调度；那些是同一过程落到基础设施后的升级模型，见 [推理基础设施与 Agent 延迟](inference-infrastructure-and-agent-latency.md)。

接下来只需要顺着三个问题读：

1. **模型把什么学进了参数？** → 权重是什么
2. **一次预测内部怎样流动？** → 推理的完整过程、Transformer、Attention
3. **为什么同一个模型会给出不同答案？** → 采样参数与生成策略

## 权重是什么

### 定义

**权重**：模型在训练中学到的大量数值参数。推理时它们通常保持不变，共同决定输入经过每一层后怎样被转换。

不同模型的参数规模和内部结构差异很大；许多闭源模型并不公开准确参数量。理解推理不需要先知道某个产品的具体数字，只需要记住：**答案不是存放在某一个参数里，而是大量参数共同计算出来的。**

### 权重 vs 知识

**误解**：
```
❌ 知识像文件一样存在模型的某个地方
❌ 比如"巴黎是法国首都"存在某个权重里
```

**真相**：
```
✅ 知识分散在所有权重的组合里
✅ "巴黎是法国首都"这样的关系
   通常分布在模型的内部表示与参数组合中
   不能简单指向某一个权重
```

**比喻**：
```
不像书的某一页写着"巴黎是首都"
而是像一个人脑子里
通过大量连接共同形成关联
才能理解"巴黎"和"首都"的关系
```

### 权重怎么来的：训练

**过程**：

```
初始状态：
  权重 = 随机数
  模型什么都不懂

训练循环：
  1. 读一句话
  2. 用现有权重预测下一个词
  3. 预测错了
  4. 计算损失（错得有多离谱）
  5. 反向传播：从错误往回追
     → 找出哪些权重该负责
     → 往正确方向微调一点点
  6. 在大量 Token 和训练批次上重复

结果：
  权重从随机数 → "懂语言会推理"的知识网络
```

**关键点**：
```
- 每次微调的幅度很小（学习率）
- 在大规模数据上反复更新
- 反向传播计算梯度（权重该怎么改）
- 完成训练并部署后，推理阶段通常不再修改权重
```

这里只是训练的核心循环——预训练怎么用这个循环、监督微调和 RLHF 又是怎么回事、训练为什么这么贵，见 [Training 训练系统完全指南](training-system-guide.md)。

### 推理 vs 训练中的权重

```
训练中：
  权重 = 可变的
  用反向传播调整
  计算昂贵

推理中：
  权重 = 通常保持固定
  只有正向传播
  计算相对便宜
  但成本仍取决于模型规模、输入长度和生成长度
```

## 推理的完整过程

### 第 1 步：Tokenization（切成 Token）

```
输入："巴黎是法国首都"

Token 化：
  可能切成单字、词片段或多个字符的组合
  每个 Token 再映射成词表里的一个整数 ID
```

### 第 2 步：Embedding（变成向量）

```
每个 Token 变成一个向量
这个向量在高维空间里代表这个词的"语义位置"

Token 1024 → [0.23, -0.91, 0.15, ..., 0.78]
             （维度很高，几千维或更多）

向量空间的性质：
  "国家"相关的词在空间里聚在一起
  "首都"相关的词在另一个区域
  "巴黎"的向量靠近"首都"也靠近"法国"
```

这里的"向量"只是一次推理内部的中间步骤；把这个想法单独拿出来、用来比较整段文字的语义相似度，见 [Embeddings 完全指南](embeddings-guide.md)。

### 第 3 步：正向传播（Forward Pass）

```
向量流过 Transformer 网络
每一层做不同的事：

第 1 层：
  - Attention：词和词交互，互相影响
  - Feed Forward：每个词独立思考
  → 输出新的向量表示

第 2 层：
  - 继续交互和思考
  → 更高层的表示出现

...（重复多层；具体层数因模型而异）

最后一层：
  → 输出概率分布（下一个词是什么）
```

### 第 4 步：Attention（词和词交互）

```
每个词：
  1. 看所有已出现的词（不包括后面的）
     （生成模型是单向的）
  2. 计算"我应该关注谁"
  3. 加权求和融合信息

例子：
  当处理"首"时，Attention 发现：
    "法国"很相关（权重 0.7）
    "首都"很相关（权重 0.6）
    "巴黎"有点相关（权重 0.2）
  → 融合这些词的信息处理"首"
```

### 第 5 步：层层深化

```
浅层（第 1-10 层）：
  识别语言结构
  "这是一个陈述句"
  "主语是名词"

中层（第 10-30 层）：
  激活相关知识
  "巴黎 → 首都"
  "法国 → 国家"

深层（第 30-60 层）：
  抽象推理
  "哪个是哪个的首都"
  综合推理得出答案的概率
```

### 第 6 步：输出概率分布

```
推理完成后，输出：

{
  "巴黎": 0.89,      # 89% 概率
  "伦敦": 0.05,      # 5% 概率
  "东京": 0.03,      # 3% 概率
  "其他": 0.03       # 3% 概率
}

不是"确定"答案，而是概率分布
```

### 第 7 步：选词（用温度等参数）

```
用温度、Top-p、Top-k 决定怎么从分布里选词
（详见下面的"采样参数"）
```

### 第 8 步：一个词一个词生成

```
第 1 词：选"巴" → 加入输出，同时更新 Context

第 2 词：
  输入："问题" + ["巴"]
  输出概率分布
  选"黎"
  
第 3 词：
  输入："问题" + ["巴", "黎"]
  输出概率分布
  选"是"

...直到生成完整答案或达到 Token 限制
```

### 完整流程图

```
用户问题
  ↓
Tokenization: 切成 Token
  ↓
Embedding: Token → 向量
  ↓
第 1 层 Transformer:
  ├─ Attention（词交互）
  ├─ 残差连接
  ├─ Layer Norm
  ├─ Feed Forward（独立思考）
  ├─ 残差连接
  └─ Layer Norm
  
  → 输出更高层的表示
  ↓
第 2-N 层 Transformer:
  (重复上面的过程)
  ↓
输出层：生成概率分布
  ↓
采样：用温度、Top-p、Top-k 选词
  ↓
输出一个词，更新 Context
  ↓
重复直到完成
  ↓
最终答案
```

## Transformer 架构

### 一层 Transformer 的完整结构

```
输入向量 X
  ↓
┌─────────────────────────────────────┐
│ Multi-Head Attention                │
│ (词和词交互)                         │
└─────────────────────────────────────┘
  ↓
+ 残差连接（加上原始输入 X）
  ↓
┌─────────────────────────────────────┐
│ Layer Normalization                 │
│ (稳定数值，防止爆炸)                 │
└─────────────────────────────────────┘
  ↓
┌─────────────────────────────────────┐
│ Feed Forward Network                │
│ (每个词独立的深加工)                  │
└─────────────────────────────────────┘
  ↓
+ 残差连接（加上 Norm 前的输出）
  ↓
┌─────────────────────────────────────┐
│ Layer Normalization                 │
└─────────────────────────────────────┘
  ↓
输出向量 Y
```

### 每个组件的作用

**Multi-Head Attention**：
```
词和词交互
每个词"看"所有前面已出现的词
计算"谁应该影响我"

例子：
  处理"首都"时
  Attention 发现"巴黎"和"法国"相关
  所以在处理"首都"时融合它们的信息
```

**残差连接（Residual Connection）**：
```
X → [某个操作] → Y
↓             ↓
└─────+───────┘
      ↓
    Y + X

为什么重要：
  • 原始信息 X 可以直接传到深层
  • 防止信息在深层消失
  • 就像高速公路，让原始信息绕过一些层
  • 没有残差连接，太深的网络训练不了
```

**Layer Normalization**：
```
作用：稳定数值

比喻：
  正向传播过程中
  数字会越来越大或越来越小
  Layer Norm 把它拉回合理范围
  就像稳压器
  
结果：
  训练更稳定
  数字不爆炸
```

**Feed Forward Network**：
```
每个词独立经过的非线性网络

结构：
  向量 → 线性变换 → ReLU(激活) → 线性变换 → 输出

作用：
  Attention 是"看别人怎么想"
  Feed Forward 是"自己怎么想"
  
  具体在做什么：
    • 深加工信息
    • 学习非线性关系
    • 可能编码某些知识（待研究）
```

### 不同模型为什么长得不一样

层数、隐藏维度、Attention 头数、FFN 宽度和是否使用 MoE，都会改变模型容量、计算成本和内存需求。开源模型通常会公开这些配置；闭源模型往往不会。这里不拿某个产品的猜测数字当通用规律——理解这条主线已经够用：

```text
更深 / 更宽 / 更多专家
  → 通常带来更大的表示与学习容量
  → 同时增加训练、推理或内存成本
  → 最终效果还取决于数据、训练方法和系统实现
```

## Attention 机制

### 完整过程

```
输入：已出现的所有词 [w1, w2, ..., wn]
目标：处理词 wi，决定谁影响它

Step 1: 计算相关性分数

对于每个词 wj（j ≤ i）：
  score(wi, wj) = (wi 的特征) · (wj 的特征)
  
结果：一个分数，表示 wj 与 wi 的相关程度

Step 2: 归一化成概率

softmax([score(wi, w1), score(wi, w2), ...])
→ [0.6, 0.3, 0.05, ...]

形成概率分布：
  词 1 影响我 60%
  词 2 影响我 30%
  词 3 影响我 5%

Step 3: 加权融合

result = 0.6 * w1_value + 0.3 * w2_value + 0.05 * w3_value

得到融合后的表示
```

### 为什么是"Multi-Head"

```
不只是一种"注意力方式"
而是多种并行：

Head 1：
  可能关注"词法关系"
  "这个词的词性是什么"

Head 2：
  可能关注"语义关系"
  "这个词的意思与谁相关"

Head 3：
  可能关注"语法关系"
  "这个词与谁是主宾语"

...（通常 8-32 个头）

多个视角 → 更全面的理解
```

### Causal Attention（生成模型用）

```
生成式语言模型通常使用 Causal Attention

每个词只能看前面已出现的词：

第 1 个词：只能自己
第 2 个词：可以看第 1 个词
第 3 个词：可以看第 1、2 个词
...

为什么：
  答案是一个词一个词生成的
  后面的词还不存在
  不能"看到未来"
  
这与 BERT 这样的双向模型不同
（BERT 训练时可以双向看）
```

### Attention 的计算成本

```
N 个词，每个词要与所有词计算相关性

复杂度：O(N²)

意义：
  100 个 Token：1 万次计算
  1000 个 Token：100 万次计算
  序列越长：标准 Attention 的两两交互增长很快

这是为什么：
  Context Window 有上限
  Token 太多，Attention 计算爆炸
```

这里的 O(N²) 描述的是标准全注意力的理论交互规模。实际系统会用 FlashAttention、KV Cache、滑动窗口或稀疏 Attention 等办法减少内存开销或避免重复计算，但不会因此让“长 Context 没有代价”。

## 采样参数

### 三个参数的本质

所有参数都做同一件事：**从概率分布里选词**

模型输出：
```
{
  "巴黎": 0.40,
  "伦敦": 0.30,
  "东京": 0.20,
  "其他": 0.10
}
```

问题：选哪个词？

答案：用温度、Top-p、Top-k 决定

### 参数 1：温度（Temperature）

**工作原理**：改变概率分布的形状

```
低温度（0.1）：
  分布变得陡峭，尖锐
  { "巴黎": 0.95, "伦敦": 0.04, ... }
  → 几乎总是选最可能的词
  → 确定性强，创意低

正常温度（1.0）：
  保持原始分布
  { "巴黎": 0.40, "伦敦": 0.30, ... }
  → 按原始概率选
  
高温度（2.0）：
  分布变得平坦，均匀
  { "巴黎": 0.26, "伦敦": 0.25, ... }
  → 各个词都有机会
  → 随机性高，创意多（但可能乱说话）
```

**用途**：
```
低温：精确回答（数学题、代码）
中温：平衡创意和准确（日常对话）
高温：创意写作、头脑风暴
```

### 参数 2：Top-p（Nucleus Sampling）

**工作原理**：只从累积概率达到 p 的词里选

```
假设分布：
  "巴黎": 0.40  →累计 0.40
  "伦敦": 0.30  →累计 0.70
  "东京": 0.20  →累计 0.90
  "其他": 0.10  →累计 1.00

Top-p=0.9：
  选累计到 90% 的词
  包括："巴黎"、"伦敦"、"东京"
  排除："其他"
  从这三个词里随机选

Top-p=0.7：
  选累计到 70% 的词
  包括："巴黎"、"伦敦"
  排除：其他
  从这两个词里随机选
```

**特点**：
```
动态调整候选词数量
概率分布变化，候选词数也变化
总是保持在合理范围
```

### 参数 3：Top-k

**工作原理**：只从概率最高的 k 个词里选

```
Top-k=3：
  选概率最高的 3 个词
  "巴黎"(0.40), "伦敦"(0.30), "东京"(0.20)
  从这 3 个词随机选
  排除："其他"(0.10)

Top-k=10：
  选概率最高的 10 个词
  （如果只有 5 个词，就选 5 个）
```

**特点**：
```
固定候选词数量
简单粗暴
```

### 三个参数的对比

| 参数 | 作用 | 适合场景 |
|------|------|--------|
| **温度** | 改变概率分布形状 | 控制整体创意程度 |
| **Top-p** | 动态筛选高概率词 | 聪明的平衡策略 |
| **Top-k** | 固定数量候选词 | 简单快速的控制 |

具体产品会组合或隐藏这些参数；默认值也可能变化。概念上只需记住：它们都在调整“候选范围有多宽、选择有多确定”。

## 涌现：能力真的会“突然出现”吗？

### 先区分能力和成绩

有些 Benchmark 把连续能力压成“答对 / 答错”。模型可能一直在缓慢进步，却直到跨过评分阈值才第一次拿分，于是成绩曲线看起来像能力突然出现。

```text
底层能力：  逐渐进步  ─────────────→
评分规则：  低于门槛都记 0，跨过门槛才记 1
观察结果：  0  0  0  0  1
                     ↑
               看起来像“突然会了”
```

### 但也不能反过来说一切都连续

规模、数据、训练方法和推理方式改变后，模型确实可能在某些任务上出现非线性跃升；多个子能力组合起来，也可能让新行为第一次变得可观察。问题在于，不能仅凭一条跳跃的 Benchmark 曲线，就断言模型内部发生了明确“相变”。

### 训练损失不是万能触发器

训练损失描述模型在训练目标上的平均预测误差，它通常能帮助判断训练是否整体推进，却不能给每项下游能力提供一个通用临界值。相同或相近的损失，可能对应不同的数据组成、架构和任务表现。

### 更有用的研究态度

- 同时看连续指标和通过率，避免评分阈值制造假象
- 在不同模型规模、数据和提示方式下重复测试
- 区分“模型获得了能力”和“评测终于测到了能力”
- 把“涌现”当作待解释的观察，不当作已经知道原因的定律

## 实战理解

### Thinking 模式的原理

```
普通推理：
  问题 → 正向传播一次 → 输出答案

Thinking 模式（deep reasoning）：
  问题 → 生成更多中间推理 Token / 使用更多推理计算 → 输出答案
       ↑
       在"草稿纸"上先推理
       再输出最终答案
```

**具体过程**：
```
Step 1：用户问题进来
Step 2：模型生成更多中间推理 Token
  - 可能性 A 的理由…
  - 可能性 B 的理由…
  - 对比…
  - 最可能…
  （这些都是正向传播产物）
  
Step 3：基于推理，输出最终答案

效果：
  草稿纸越大（Token 预算越高）
  推理越深
  质量越好
  
成本：
  增加了 Token 消耗
  需要几倍的推理时间
```

不开启专门的 Thinking 模式，也能借用同一个原理——直接在 Prompt 里要求"先一步步分析，再给结论"，见 [Prompt 工程完全指南](prompt-engineering-guide.md#2-让它先想再答chain-of-thought)。

### 模型的"幻觉"为什么发生

```
例子：模型对不确定事实给出流畅但错误的回答

原因分析：
  • 模型学会了"流畅表达"
  • 但没有学会"知道自己不知道"
  • 涌现的副产品：能说话≠能说对
  
这不是模型"疯了"
而是在当前能力下的必然结果：
  模型优化的是"下一个词最可能"
  不是"下一个词最真实"
  
解决方案：
  • 人工复核永远必要
  • 用 constitution 引导价值观
  • 持续训练改进
```

### Context Window 为什么有上限

```
两个原因：

原因 1：计算量
  N 个 Token 需要 N 次正向传播
  加上 Attention 的 O(N²) 计算
  太大就算不动

原因 2：Attention 精度下降
  窗口太长，Attention"注意力"分散
  中间的信息容易被忽视
  （Lost in the Middle）
  
解决方向：
  • 更高效的 Attention（FlashAttention）
  • 稀疏 Attention（不是所有词都交互）
  • 能够处理更长序列的架构
```

### Memory vs Context vs 权重

```
权重（长期记忆）：
  • 训练时学到的大量参数
  • 部署推理时通常保持固定
  • 改变需要重新训练
  • 不会遗忘

Context（短期记忆）：
  • 这次对话的白板
  • 这次推理的输入
  • 对话结束清空
  • 容量有限

Memory System（持久记忆）：
  • 介于两者之间
  • 跨对话保存
  • 每次对话加载进 Context
  • 需要设计管理

三者配合才完整：
  权重 = 学到的"知识结构"
  Memory = "记得什么"
  Context = "现在能看什么"
```

## 关键洞察

### 推理的本质

```
不是查找数据库
不是搜索已有答案
不是简单的符号操作

而是：
  让信号流过一张固定的权重网络
  在高维抽象空间里做推理
  一个词一个词生成答案
  
每个词都是对之前 Token 和权重
交互的完整结果
```

### 涌现的启示

```
看到能力曲线突然跳升时，先问：

1. 底层能力变了，还是评分门槛被跨过了？
2. 规模之外，数据、训练方法和推理预算变了吗？
3. 换一种连续指标，跳跃还存在吗？
4. 这个现象在不同模型和任务上能复现吗？
```

### 为什么需要人工复核

```
Inference 的局限：
  • 优化的是"流畅"而不是"真实"
  • 在不知道答案时也能自信地说话
  • 容易幻觉
  • 知识可能过时
  • 推理可能有逻辑漏洞

解决方案：
  • 不能完全自动化
  • 需要人在关键决策点
  • 需要检查重要信息
  • 需要多来源验证
```
