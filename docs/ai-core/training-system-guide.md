# Training 训练系统完全指南

**核心概念**: 模型从"一堆随机数"变成"能聊天的助手"，要走三个阶段——**预训练**（在海量文本上自己跟自己学语言）、**监督微调**（教它像助手一样说话）、**RLHF**（用人类反馈打磨成"讨人喜欢"）。"权重怎么调整"这个循环，[Inference 完全指南](inference-system-guide.md) 已经讲过；监督微调和 RLHF 的具体三步流程，[Evaluation 系统](../ai-research/evaluation-system.md) 也已经讲得很细。这篇要补的是：预训练本身到底在干什么、把三个阶段串成一条完整的线，以及为什么训练一个前沿模型要烧掉这么多钱。

**关键洞察**: 预训练不需要人工标注"标准答案"——它是自监督的，互联网上的文字本身就是"正确答案"（下一个词是什么，原文里已经写好了）。真正需要人工介入、教模型"怎么当好助手"的，是后面监督微调和 RLHF 这两步，而这两步用的数据量，比预训练小好几个数量级。

**第一次接触这个主题？** 建议先了解：[LLM](../../glossary.md#llm) · [Inference](../../glossary.md#inference) · [Model](../../glossary.md#model)

## 训练的核心循环（快速回顾）

[Inference 完全指南](inference-system-guide.md) 已经讲过这个循环，这里只提炼成一句话：**权重从随机数开始，模型预测下一个词，跟正确答案比对算出"错得有多离谱"（损失），反向传播把这个误差翻译成"每个权重该往哪个方向调一点点"，重复几万亿次。** 训练这三个阶段（预训练、微调、RLHF），用的都是这同一个循环，区别只在于：**喂给它的数据长什么样、"正确答案"从哪来**。

## 预训练：从随机数到"会说话"

**预训练（Pretraining）**是三个阶段里最大、最贵、也是唯一不需要人工标注的一步。

**数据从哪来**：互联网上的网页、书籍、代码仓库、论文——量级是几万亿个 Token。这不是精心挑选的"教材"，是尽可能多、尽可能杂的文字。

**"正确答案"从哪来**：这是预训练最关键的一点——**不需要人工写答案**。给模型一段已经存在的真实文本，把其中一个词盖住，让模型猜；猜完了，答案就是原文里那个词本身。互联网上的每一句话，天然自带"正确答案"，这就是为什么这一步能用到万亿级的数据量而不需要雇人标注——这种"答案就藏在数据本身里"的训练方式，叫**自监督学习（Self-supervised Learning）**。

**训练完得到什么**：一个"读过互联网上几乎所有文字"、能流畅接话的模型，术语叫**基础模型（Base Model）**。但这时候的它，只是"很会接话"，不等于"很会当助手"——你问它一个问题，它可能会把这当成"网上常见的一段文字"来续写，而不是老老实实回答你。这就是为什么还需要后面两步。

## 监督微调与 RLHF：从"会说话"到"说人话"

从基础模型到一个"像 Claude/ChatGPT 这样的助手"，还要走两步——这两步的具体三阶段流程（监督微调 → 奖励模型 → 强化学习），[Evaluation 系统](../ai-research/evaluation-system.md) 已经写得很细，这里只讲这两步在整条训练线上扮演什么角色：

- **监督微调（SFT，Supervised Fine-tuning）**：这次不再是"互联网文字自带答案"，是人工写的"这才是助手该有的回答"样本，数量比预训练小得多。模型在这些样本上继续训练，从"很会接话"变成"知道该怎么像助手一样回答问题"。
- **RLHF（基于人类反馈的强化学习）**：再往上一层——不只是"模仿人工写的标准答案"，是让模型生成多个回答，人类（或训练出来的打分模型）挑出更好的那个，模型继续调整，学会"人类更喜欢哪种说法"。这一步是模型"讨人喜欢""知道什么不该说"这些特质的主要来源。

**一条线连起来看**：预训练给了模型语言能力和世界知识的底子（贵，量大，不需要人工标注）；监督微调教会它"助手应该怎么说话"（相对便宜，量小，需要人工样本）；RLHF 再打磨成"人类更喜欢的样子"（同样需要人工反馈，但反馈的是"排序偏好"而不是"标准答案"）。三步用的都是同一套"预测→出错→调整"循环，只是数据的来源和"正确答案"的定义，一步比一步更依赖人。

## 为什么训练这么贵

预训练阶段之所以要花上千万甚至上亿美元，直接对应到 [Computing Foundations](../computing-foundations/index.md) 已经讲过的几件事——这也是为什么这个 Wiki 先花大力气讲硬件基础的原因，这里正好是它派上用场的地方：

- **算力**：预测下一个词，本质是海量的矩阵乘法，要在万亿级 Token 上重复几万亿次——这正是 [FLOPS 与精度](../computing-foundations/flops-and-precision.md) 讲的"每秒能做多少次运算"要直接拿来算账的场景。
- **规模**：一个模型的训练不可能在一块 GPU 上跑完，往往要成百上千块卡同时算，而且每一轮还要互相同步梯度——这正是 [从 1 卡到千卡](../computing-foundations/scaling-and-communication.md) 讲的通信开销和阿姆达尔定律，在训练场景里的真实样子。
- **内存**：权重、每一步的中间结果（激活值）、优化器自己的状态，都要塞进显存、并且要喂得够快——这正是 [内存墙](../computing-foundations/memory-wall.md) 讲的"算得快不代表喂得饱"，训练时同样成立，甚至比推理更吃紧（推理只需要权重，训练还要额外存住优化过程中的中间数据）。

这也是为什么预训练只有少数几家公司能做——不是技术门槛的问题（循环本身不复杂），是硬件门槛：需要同时买得起、管得好几千块卡的规模，这些恰好是 Computing Foundations 五条主脊分别在讲的东西。相比之下，监督微调和 RLHF 数据量小得多，需要的算力也小得多——这也是为什么"微调一个已有模型"比"从头训练一个模型"便宜得不是一星半点。

## 训练完之后：权重冻结与知识截止日期

[Inference 完全指南](inference-system-guide.md#推理-vs-训练中的权重) 已经提过：训练时权重是可变的，训练一结束，权重就完全固定下来，推理时只做正向传播，不再调整。这带来一个直接后果——**知识截止日期（Knowledge Cutoff）**：模型知道的世界，停在了训练数据收集的那个时间点，之后发生的事，它不会自己知道，除非你在对话里告诉它，或者靠 Tool/RAG 这类机制去外部查（[术语表 RAG](../../glossary.md#rag)）。

想让模型"学会"新东西，唯一的办法是重新走一遍训练循环——不是改一个配置文件就行，这也是为什么"更新模型"是一件成本很高的事，直接呼应上一节"为什么训练这么贵"。
