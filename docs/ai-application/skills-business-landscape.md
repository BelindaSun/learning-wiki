# Skills 和商业格局

**核心概念**: 模型公司吃智能的钱，集成商吃信任和关系的钱，会写 Skills 的普通用户省掉中间商。Skill 是入口，服务才是护城河。

**学习来源**: @cellier_ 的帖子 + Claude 延伸讨论  
**最大收获**: "透明"的新用法——中间层对用户透明，不是说它不存在，而是说你感知不到它、也不需要跟它打交道。

## Skill 是什么（基础概念）

如果你还不知道 Skill 是什么，这里先补一下背景，再往下看商业分析会更顺。

**一句话**：Skill 是给 Claude 打包的一套"怎么做某件事"的说明书——把一个具体任务（写周报、翻译文档、分析财报……）需要的步骤、规则、格式要求都写清楚，存成一个可复用的文件，以后让 Claude 执行这个任务时直接照着做，不用每次重新解释一遍。

**类比**：
- 没有 Skill：每次都要跟 Claude 从头讲清楚"我要什么风格的翻译、术语怎么处理、格式要求是什么"
- 有 Skill：把这些规则写一次、存起来，以后说"用我的翻译 Skill"，Claude 直接照着执行

**Skill 能做什么**：定义一个操作或[工作流](../../glossary.md#workflow)、调用大模型、调用外部[工具](../../glossary.md#tool)（读文件、查数据等）、按你定的规则返回结果。

**Skill 不能做什么**：存储私密数据、进入企业内部系统、承担法律责任、提供超出规则之外的个性化服务。

理解了这个基础定义，下面聊的是更深一层的问题：Skill 这么容易写，会不会导致"人人都能做同样的事，谁也赚不到钱"？这就是接下来要拆开讲的三层商业格局。

## 三层商业格局

### 完整图景

```
┌─────────────────────────────────────┐
│ 顶层：模型公司                       │
│ (Claude, GPT, Gemini...)           │
│ 吃：智能的钱                         │
│ 赚：API 调用费、模型订阅费           │
└─────────────────────────────────────┘
           ↑ 调用 API
           │
┌─────────────────────────────────────┐
│ 中层：集成商                         │
│ (行业解决方案、垂直 SaaS)            │
│ 吃：信任和关系的钱                   │
│ 赚：解决方案费、服务费、咨询费       │
└─────────────────────────────────────┘
           ↑ 集成方案
           │
┌─────────────────────────────────────┐
│ 底层：个人用户/小团队               │
│ 直连顶层写 Skills                   │
│ 省：中间商费用                       │
│ 做：个人项目、小工具、内部系统       │
└─────────────────────────────────────┘
```

### 顶层：模型公司

**他们做什么**：
```
• 训练大模型
• 提供 API
• 持续优化能力
• 提供开发工具（MCP、Skills 等）
```

**怎样赚钱**：
```
• API 调用费（按 Token 计算）
• 模型订阅费（Pro、Team、Enterprise）
• 企业定制服务
```

**为什么赚钱多**：
```
✓ 智能本身有价值
✓ 所有人都需要
✓ 规模经济（固定投入，边际成本极低）
✓ 很难被替代（需要数万亿 Token 训练）
```

**现状**：
```
两三个玩家通吃
• Claude (Anthropic)
• GPT (OpenAI)
• Gemini (Google)
• 其他都比较小
```

### 中层：集成商

**他们做什么**：
```
• 理解行业痛点
• 把大模型集成进行业系统
• 处理数据进去的问题
• 为结果负责任
```

**怎样赚钱**：
```
• 咨询费（"怎样用 AI"）
• 集成服务费（"帮我接上去"）
• 维护和优化费（"一直保证能用"）
• 数据处理费（"怎样让我的数据进去"）
```

**关键优势**：
```
✓ 理解行业
✓ 有权限进入行业系统
✓ 敢承担责任（出了问题谁负责）
✓ 有既有的客户关系
✓ 用户相信他们（信任成本已付出）
```

**为什么模型公司无法替代他们**：
```
模型公司的问题：
  ✗ 不懂这个行业
  ✗ 进不了企业内部系统
  ✗ 拿不到行业的私密数据
  ✗ 不想承担法律责任
  ✗ 不负责售后和维护
```

### 底层：个人用户/小团队

**他们做什么**：
```
• 写 Skills 直连顶层
• 为自己或小团队解决问题
• 不需要去中间商
```

**成本**：
```
✓ 极低
  • 只需要付 API 调用费
  • 不需要付集成商的溢价
  • 自己的时间成本
```

**限制**：
```
✗ 只能做"没有法律风险"的事
✗ 只能用"能从外部获取"的数据
✗ 不能做"需要进企业系统"的事
✗ 不能做"需要承担责任"的事
```

### "透明"的新含义

**旧概念**：
```
某个系统"对用户透明"
= 用户看不见它
= 它不存在
```

**新概念**（三层格局里）：
```
中间层"对用户透明"
= 用户感知不到它的存在
= 但它其实在那儿
= 用户也不需要跟它打交道

例子：
  如果你会写 Skills
  集成商这一层对你"透明"
  你也不需要它
  
  但如果你是大企业
  集成商这一层对你"不透明"
  你能看到、也需要交互
```

## 垂直 vs 通用 Agent

### 定义

**通用 Agent**：
```
用通用大模型 + 通用工具 + 通用 Skills
适应各种不同的任务
例：Claude、GPT、Mimo

特点：
  ✓ 灵活
  ✓ 快速适应新领域
  ✗ 对某个领域不够深
```

**垂直 Agent**：
```
针对某个行业/领域的专用 Agent
例：医疗 AI、法律 AI、财务 AI

特点：
  ✓ 深入某个领域
  ✓ 能处理行业特定的问题
  ✗ 迁移到其他领域困难
```

### 本质区别（不是能力的问题）

**误解**：
```
❌ 垂直 Agent 是"更聪明的模型"
❌ 通用 Agent 是"不够聪明"
❌ 能力来源相同，只是专精程度不同
```

**真实**：
```
✅ 能力的来源不同

通用 Agent 的能力来源：
  • 大模型的通用理解
  • 通过 Tool Use 调用外部工具
  • 不需要领域专有知识

垂直 Agent 的能力来源：
  • 行业特定的数据
  • 行业特定的规则
  • 行业特定的模型（可能更小）
  • 行业特定的权限
```

### 垂直 Agent 的真实护城河

**不是**：
```
❌ 一个更聪明的模型
❌ 更好的 Prompt
❌ 更多的 Skills
```

**是**：
```
✅ 数据权限
   "只有我们有这个行业的数据"
   
✅ 系统集成
   "只有我们能进入这个企业系统"
   
✅ 法律责任
   "我们敢为结果负责"
   
✅ 资质和认证
   "我们是合法的医疗/法律/金融服务商"
   
✅ 用户信任
   "我们已经是这个行业的服务商"
```

### 为什么通用模型会赢

```
但不是"替代垂直 Agent"
而是"被垂直 Agent 集成"

趋势：
  2024: 垂直 Agent 用自己的模型或小模型
  2025: 垂直 Agent 开始用大模型 API
  2026: 大多数垂直 Agent 都在用大模型

为什么：
  ✓ 大模型太聪明了，付钱用比自己训练便宜
  ✓ 大模型持续进步，不用维护
  ✓ 只需要在"大模型 + 行业数据 + 行业规则"的组合上优化
  
结果：
  • 大模型赢
  • 但赢的方式是"被嵌入到垂直解决方案里"
  • 不是"替代"，是"被集成"
```

## Skill 的本质

### Skill 只是入口

**一个 Skill 能做的**：
```
• 定义一个操作或工作流
• 调用大模型
• 调用外部工具
• 返回结果

举例：一个"翻译文档"的 Skill
  • 接收中文文档
  • 调用 Claude 翻译
  • 返回英文文档
```

**一个 Skill 不能做的**：
```
• 存储私密数据
• 进入企业系统
• 承担法律责任
• 提供个性化服务
• 长期维护和优化
```

### 复制成本有多低

```
一个 Skill 能被复制吗？
答案：秒秒钟

例子：翻译工具 Skill
  你写了一个："我的翻译工具"
  其他人可以在 30 分钟内写出完全一样的
  
为什么：
  ✓ 逻辑简单
  ✓ 工具都是公开的
  ✓ Prompt 可以优化但差别不大
  ✓ 没有专属数据
```

### 所以 Skill 单独没有护城河

```
单纯做一个 Skill 作为产品：
  ✗ 很容易被复制
  ✗ 很容易被 Skill 市场里的"同类产品"超越
  ✗ 用户没有理由非要用你的
  ✗ 价格战马上开始
  ✗ 最后都是免费的
```

## 护城河在哪里

### Skill 后面接的东西

**护城河 1：私有数据**

```
例子：AI2030 的 Brief
  Skill 本身：爬网页、总结信息
  • 这个任何人都能写
  
  护城河：你选择了哪些数据源
  • 付费数据源（彭博、理财通）
  • 私有数据源（你自己的研究）
  • 这个只有你有
```

**护城河 2：执行服务**

```
例子：翻译工具 Skill
  Skill 本身：调用翻译模型
  • 这个任何人都能写
  
  护城河（如果有）：
  ✓ 可能是：背后有真人翻译团队
  ✓ 可能是：你理解某个领域的行话
  ✓ 可能是：你能进入企业系统执行翻译
```

**护城河 3：行业资质**

```
例子：医疗 AI Agent
  Skill 本身：用 Claude 回答医学问题
  • 这个技术上任何人都能做
  
  护城河：
  ✓ 你是持证的医疗机构
  ✓ 你有医生团队审核 AI 的输出
  ✓ 你能为结果负法律责任
```

**护城河 4：用户信任**

```
例子：Mimo（家庭 AI）
  Skill 本身：各种对话和决策函数
  • 技术上任何人都能做
  
  护城河：
  ✓ 用户已经在用 Mimo
  ✓ Mimo 已经"记住"了这个家庭的历史
  ✓ 用户信任 Mimo 理解他们
  ✓ 迁移成本很高
  
  这就是为什么 Mimo 即使小
  也不会被大 AI 秒杀
```

### 具体例子：翻译工具 Skill

**没有护城河的版本**：
```
功能：把中文翻成英文
技术：调用 Claude API
成本：每次调用付 Token 费

问题：
  ❌ 任何人都能在 30 分钟写出来
  ❌ 用户可能直接用 Claude
  ❌ 没有理由用你的工具
  ❌ 适合自用，不适合作为生意
```

**有护城河的版本**：
```
功能：把中文翻成英文
+ 技术翻译服务（理解行业术语）
+ 真人翻译师审核关键部分
+ 集成进企业翻译系统
+ 承诺准确率 99.9%

护城河：
  ✓ 你雇了懂这个领域的翻译师
  ✓ 你能进入客户的系统
  ✓ 你敢为质量负责
  ✓ 用户信任你的品牌
  
这样才能成为一个生意
```

## 会消失的是什么

### 套壳产品

**定义**：
```
既没有顶级智能
也没有真实行业壁垒
只是套一层模型 API 的东西
```

**具体例子**：
```
• 某个"翻译工具"：就是调用 OpenAI，加个网页
• 某个"写作助手"：就是调用 Claude，加个格式化
• 某个"客服 Bot"：就是调用某个 API，加个客服系统的皮
• 某个"行业 AI"：号称懂行业，实际就是加了行业词汇的通用模型
```

**为什么会消失**：
```
原因 1：智能无法垄断
  • 任何人都能用大模型 API
  • 套壳产品的"聪明"来自 API
  • 用户可能直接用 API，不需要中间层
  
原因 2：没有数据护城河
  • 没有私有数据
  • 没有行业特殊权限
  • 没有真实用户信任基础
  
原因 3：成本结构不好
  • 要雇人维护
  • 要投入市场推广
  • 利润被 API 成本压低
  • 无法和大公司竞争
```

### 会活下来的是什么

**活下来的三种**：

**类型 1：顶层（模型公司）**
```
• Claude、GPT、Gemini
• 两三家通吃
• 赚智能的钱
```

**类型 2：真正的集成商**
```
• 有真实行业壁垒
• 有数据权限或系统权限
• 敢为结果负责
• 有既有客户基础

例子：医疗 AI（需要医生）、金融 AI（需要数据权限）
```

**类型 3：会写 Skills 的个人/小团队**
```
• 为自己或小团队解决问题
• 成本极低
• 灵活快速

例子：Belinda 的 AI2030、Mimo
```

## 实战例子

### 例 1：Mimo（会活下来）

**什么在**：
```
✓ 私有数据（家庭历史、记忆）
✓ 用户信任（已经用了，舍不得）
✓ 个性化（理解这个家庭）
✓ 持续价值（越用越懂）
```

**为什么有护城河**：
```
• 任何人都能写一个"家庭 AI"
• 但无法复制你家庭的历史
• 无法复制你对 Mimo 的信任
• 迁移成本很高
```

**商业可能性**：
```
• 个人使用：完全免费或很便宜
• 企业/机构使用：可能值钱
  （比如养老院、教育机构需要这样的 AI）
```

### 例 2：AI2030（可能活下来）

**什么在**：
```
✓ 私有数据源（选择的信息源）
✓ 个性化判断（你的投资哲学）
✓ 持续优化（逐渐改进）
✓ 信任基础（你写的东西，别人可能买）
```

**为什么有护城河**：
```
• Skills 本身任何人都能写
• 但你的数据源选择别人无法复制
• 你对数据的判断力无法复制
• 用户相信"Belinda 的 Brief"这个品牌
```

**商业可能性**：
```
• 个人创作：可能有订阅用户
• 结合行业服务：可能成为"投资咨询"的一部分
```

### 例 3：某个"翻译工具 Skill"（会消失）

**什么在**：
```
✗ 没有私有数据
✗ 没有技术门槛（就是调 API）
✗ 没有用户信任
✗ 没有行业资质
```

**为什么没有护城河**：
```
• 任何人都能写
• 用户可能直接用 Claude
• 没有理由付钱给你
```

**可能的存活方向**：
```
✓ 添加真人翻译服务
✓ 进入企业系统
✓ 专注某个行业（技术、法律、医学）
✓ 建立品牌和信任
→ 这样才可能成为"有护城河的垂直 Agent"
```

## 关键洞察

### 模型公司会赢，但方式出乎意料

```
你可能认为：
  大模型会直接替代所有人工智能应用

实际情况：
  大模型赢的方式是"被集成"
  最终赢家是"聪明地用大模型的人"
  不是"大模型本身"
```

### Skill 改变的是什么

```
之前：
  想要一个 AI 工具 → 找公司 → 付钱
  
现在：
  想要一个 AI 工具 → 自己写 Skill → 几分钟
  
这意味着：
  ✓ 普通人的权力上升
  ✓ 中间层的压力上升
  ✓ 真正有价值的中间层必须有护城河
```

### 为什么你的产品可能活下来

```
Mimo、AI2030 会活下来
不是因为"比大模型聪明"
而是因为：

✓ 它们有私有数据（家庭历史、投资记录）
✓ 它们有用户信任（持续使用）
✓ 它们有个性化（理解你独特的需求）
✓ 它们有持续价值（越用越好）

这些，大模型 API 永远无法直接复制
```
