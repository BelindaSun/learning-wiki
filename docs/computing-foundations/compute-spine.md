# 算力脊 · Compute Spine

**核心概念**: AI 为什么需要这么多计算？现代硬件怎样把这些计算做得越来越快？为什么纸面上的巨大算力又不等于模型一定跑得快？这条脊建立理解 AI 硬件所需的最小计算地基。

---

## Compute 到底是什么？

Compute 不是 GPU，也不是 FLOPS。

Compute 的本质是：**硬件执行运算，把输入变成输出。** 对于现代 AI，大量计算工作最终会被组织成矩阵乘法和其他张量运算。

但在讨论具体硬件之前，先建立一个贯穿整条脊的基本区分：

- **Workload（工作量）**：一项任务总共需要完成多少计算。训练一个大模型和用它做一次推理，workload 差好几个数量级。
- **Throughput（吞吐量）**：硬件单位时间能够完成多少计算。同一个 workload，在不同硬件上跑，throughput 不同，完成时间就不同。

"总共有多少活"和"每秒能干多少活"不是一回事。这个区分会在后面每一层反复出现。

## 为什么 GPU 特别适合 AI？

[Foundation Zero](foundation-zero.md) 已经建立了第一个近似：GPU ≈ 很多计算可以同时做。

这条脊要把这个近似升级，但不是否定它：

```
Foundation Zero:
GPU ≈ 很多计算可以同时做

        ↓ 升级

Compute Spine:
GPU 的优势不是简单"核更多"，
而是一整套针对高吞吐并行 workload 的架构取舍，
并进一步加入针对矩阵计算的专用执行单元。
```

核心不是"CPU 核少 → GPU 核多"，而是：**CPU 和 GPU 是针对不同 workload 做出的不同架构取舍。**

- CPU：把更多芯片资源投入复杂控制（分支预测、乱序执行），强调通用性和低延迟
- GPU：把更多芯片资源投入大规模并行算术，强调 throughput

现代神经网络的大量计算——矩阵乘法及相关张量运算——恰好具有高度并行、运算规整、数据可复用的特点，正是 GPU 架构的设计甜区。

完整展开 → [CPU vs GPU：为什么 GPU 赢了深度学习](cpu-vs-gpu.md)

## 为什么低精度可以让计算更高效？

选定了 GPU 之后，还有另一个维度可以提高效率：用更少的 bit 来表示每个数字。

降低精度的收益来自两个方向：

1. **数据搬运更省**：数字更小，占用更少内存，同样的内存带宽能搬更多数据——这一半的故事指向 → [内存脊](memory-spine.md)
2. **计算吞吐量更高**：如果硬件提供了对应的低精度执行路径（尤其是 Tensor Core 等专用硬件），单位时间可以完成更多运算

但低精度并不会凭空让任何硬件都按固定比例变快——实际加速取决于硬件是否支持、workload 是否适合、以及系统瓶颈在哪里。

代价是数字表示得没那么精确，模型质量可能受影响——什么时候可以接受、什么时候不行，是量化（Quantization）要回答的问题，见 [Models 深挖](../ai-research/models-deep-dive.md#技术-3量化quantization)。

完整展开 → [FLOPS 与精度：为什么降精度能提速](flops-and-precision.md)

## 为什么 FLOPS 不等于真实速度？

一块 GPU 标着几百甚至几千 TFLOPS（每秒万亿次浮点运算），但真实模型运行时往往远达不到这个数字。为什么？

因为 FLOPS 衡量的是硬件在特定条件下理论上的峰值吞吐量——但真实 workload 运行时，计算单元不是每一刻都在满负荷工作。它们可能在**等**：

```
硬件有一个理论天花板
        ↓
但真实 workload 往往达不到
        ↓
因为计算单元可能在等
```

等什么？三个最重要的原因：

| 计算单元在等什么 | 对应哪条脊 |
|------------------|-----------|
| **数据没到**——数据从内存搬到计算单元的速度跟不上 | → [内存脊](memory-spine.md) |
| **别的设备还没算完**——多设备之间需要同步和通信 | → [规模脊](scale-spine.md) |
| **软件没有把硬件充分用起来**——编译器/kernel 不够成熟、调度不够好 | → [软硬桥脊](bridge-spine.md) |

这一节只做一件事：**打掉"TFLOPS 越大 = 模型一定越快"的错误 mental model。** 三个原因的具体展开，各自在对应的脊里。

## 四条脊各管什么

```
Compute     算得有多快
Memory      数据搬得有多快
Scale       很多设备怎样协同工作
Bridge      软件怎样安排工作，让硬件真正发挥能力
```

算力脊只管"算"这一个维度。其他三条脊各自管一个让计算单元"等"的原因。

## 读完应该能回答

1. **AI 为什么需要大量计算？** —— 神经网络的大量计算被组织成矩阵乘法和张量运算，参数越多、输入越长，workload 越大
2. **GPU 为什么特别适合？** —— 不是"核更多"，而是一整套针对并行 workload 的架构取舍 + 专用矩阵硬件
3. **为什么低精度能更高效？** —— 数据搬运更省 + 硬件提供低精度执行路径，但实际效果取决于硬件支持和系统瓶颈
4. **为什么 TFLOPS 不等于真实速度？** —— 计算单元可能在等数据、等通信、等软件把活安排好
