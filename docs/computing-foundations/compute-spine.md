# 算力脊 · Compute Spine

**核心概念**: 深度学习的核心运算是矩阵乘法——同一种简单运算重复几十亿次。这条脊回答两个问题：为什么 GPU 这种"海量精简核心"的架构恰好赢了这场仗，以及为什么把数字的精度调低，同一块 GPU 还能再快一截。两个问题背后是同一条逻辑线：**并行度 × 每次运算的位宽 = 实际吞吐量**。

---

## 这条脊的逻辑线

```
（核 / 并行 —— 已在 Foundation Zero 认识）
        ↓
   CPU vs GPU：两种不同的设计取舍
   （少而重的核 vs 多而轻的核）
        ↓
   FLOPS × 精度：同一块 GPU，精度调低为什么还能更快
   （并行是"同时用多少核"，精度是"每个核一次处理多宽的数字"）
```

这两篇不是孤立的两个话题，而是同一条逻辑的两层推进：

1. **第一层**：深度学习最吃的是矩阵乘法——同一条指令在海量数据上重复执行。CPU 为通用性优化（分支预测、乱序执行），GPU 为吞吐量优化（大量精简核心并行），矩阵乘法正好踩中 GPU 的设计甜区。这是"**用什么硬件**"的问题。

2. **第二层**：选定了 GPU 之后，还有一个维度可以继续榨吞吐量——把每个数字的位宽降低（FP32 → FP16 → INT8），同样宽的计算通道能同时塞下更多数字、同样的内存带宽能搬运更多数据、硬件还专门为低精度开了快车道。这是"**用什么精度**"的问题。

两层加在一起，就是现代 AI 硬件"又多又快"的基本原理：先靠并行度（GPU 架构）把同时做的运算数量堆上去，再靠降精度把每次运算的效率再拉一截。

## 两个问题，两篇文章

| 问题 | 文章 | 关键结论 |
|------|------|----------|
| 为什么 GPU 赢了深度学习？ | [CPU vs GPU](cpu-vs-gpu.md) | GPU 和 CPU 是两种不同的设计取舍——GPU 把芯片资源换成海量精简核心，矩阵乘法恰好需要这种"同一运算重复做几十亿次"的并行能力 |
| 为什么降精度能提速？ | [FLOPS 与精度](flops-and-precision.md) | 数字变小 → 同时塞得下更多 + 搬得更快 + 硬件专门开了快车道，三条一起推 |

## 这条脊不展开什么

- **矩阵乘法本身**——已经在 [Foundation Zero](foundation-zero.md) 和 [CPU vs GPU](cpu-vs-gpu.md) 里讲过，不单独开页
- **加速器种类对比（TPU、专用 ASIC 等）**——[Hardware Map](hardware-map.md) 已经在认识级别提过，逐一深挖不属于"理解现代 AI 算力所需的最小知识集"
- **精度降低对模型准确率的影响**——那是量化（Quantization）要回答的问题，见 [Models 深挖](../ai-research/models-deep-dive.md#技术-3量化quantization)

## 这条脊跟其他脊的关系

算力脊回答的是"算得有多快"。但算得快不代表整个系统就快——数据搬不到计算单元，算力再高也是闲着等（→ [内存脊](memory-spine.md)）；一台机器算得快，不等于千台机器一起算就能快千倍（→ [规模脊](scale-spine.md)）；GPU 硬件再强，软件栈（编译器/kernel/框架）跟不上也发挥不出来（→ [软硬桥脊](bridge-spine.md)）。四条脊各管一个瓶颈，算力脊只管"算"这一个维度。
