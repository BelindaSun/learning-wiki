**核心概念**: 不是完整的计算机科学基础，而是一张足够简单、足够准确、能撑住后续 AI 学习的第一张计算机地图。

## 5 组原子：概念本身

比喻帮助建立直觉，但比喻不是定义。下面把每组拆开，逐个概念给出实际定义。

### 硬件 / 软件

**硬件（Hardware）**

计算机中实际存在的物理设备——CPU 芯片、内存条、硬盘、主板、显卡，都属于硬件。

**软件（Software）**

运行在硬件上的程序，以及和这些程序相关的数据、配置。软件规定硬件在这一次具体该做什么——硬件像乐器，软件像乐谱：乐器决定了能演奏出什么范围的声音，乐谱决定这一次具体弹什么。

这里要避免一个常见的错误心智模型："硬件不重要，软件才决定能力"——这个说法不准确。GPU、TPU、NPU、ASIC 这些不同的硬件设计，本身就会带来不同的计算能力和适用任务，硬件设计本身在改变系统能做到什么。更准确的核心模型是：**硬件提供计算能力，软件告诉硬件这一次具体执行什么任务**。

### CPU / 内存 / 存储

**CPU（Central Processing Unit，中央处理器）**

真正执行指令、做运算的芯片。CPU 每次能做的事很基础（加法、比较大小、跳转到另一条指令……），复杂功能都是由海量这类基础指令组合出来的。

**内存（RAM，Random Access Memory）**

临时存放"当前正在处理"的数据的高速存储。你打开的每个 App、正在编辑的文档，此刻都占用着一块内存——关机或断电，内存里的内容全部清空，这是内存和存储最大的区别。

**存储（硬盘 / SSD，Solid State Drive 固态硬盘）**

长期保存数据的介质。断电不丢失，但读写速度比内存慢得多（尤其是老式机械硬盘）。你保存的文件、安装的 App，不用的时候都躺在存储里，用的时候才被读进内存。

### 代码 / 程序 / 进程 / OS

**代码（Code）**

人写给计算机的指令表达，比如一行 `print("hello")`。人写的源代码本身不能直接运行，需要先经过编译或解释，才能变成处理器能执行的机器指令：

```
Source Code
    ↓
Compiler / Interpreter
    ↓
Machine Instructions
    ↓
CPU
```

这里不展开编译器、解释器、机器码的技术细节——只需要知道一件事：你写的 Python / C 代码，并不是 CPU 能直接"看懂"的东西，中间还要经过一层转换。

**程序（Program）**

一套能让计算机完成某项任务的指令，比如电脑或手机中安装的一个应用程序。程序没有运行的时候，是静态存在的；当它真正开始运行，就会产生进程。

**进程（Process）**

一个正在运行的程序实例。同一个程序可以同时运行多次，每一次运行都会形成一个独立的进程，各自占用自己的内存和 CPU 时间，互不干扰。程序是静态的，进程是程序运行起来之后的状态。

假设电脑里装了一个"计算器"程序：

```
计算器程序
     │
     ├── 打开一次 → Process 1
     │
     └── 再打开一次 → Process 2
```

三者放在一起看：

```
Program
静静存在

    ↓ 运行

Process
真正开始工作

    ↓ 需要资源

Operating System
负责协调 CPU、内存、存储等资源
```

**操作系统（OS，Operating System）**

负责管理计算机资源，并为正在运行的程序提供使用这些资源的环境。这里不展开 kernel、scheduler、virtual memory 这些机制——只需要知道操作系统是硬件和运行中的程序之间的重要管理层。

### 客户端 / 服务器 / 网络 / API

**客户端（Client）**

发出请求、使用某项服务的一方，比如你的浏览器、手机 App。

**服务器（Server）**

提供服务并响应请求的一方。服务器程序通常运行在一台或多台计算机上，所以日常语言里，我们也经常把运行服务器程序的那台计算机叫做"服务器"——但要注意，**Client / Server 首先是两种角色，不是两种固定的机器**。同一台计算机在不同场景下，既可以扮演客户端，也可以扮演服务器。

```
Your App (Client)
    ↓ request

Server
    ↓ response

Your App
```

这里不深入 distributed systems（分布式系统）。

**网络（Network）**

让不同设备或程序之间能够交换数据的通道，比如互联网、Wi-Fi、局域网。

```
Client
    ↓
Network
    ↓
Server
```

这里不加入 TCP/IP、HTTP、DNS、port、socket 这些——它们属于更深入的 Software / Network Foundations。

**API（Application Programming Interface，应用程序接口）**

一个软件向其他软件开放功能时，双方约定好的调用方式和规则。Web API 是最容易理解的场景，但 API 并不只存在于客户端和服务器之间。编程库、操作系统和各种软件服务都可以提供 API。以后学到 SDK、MCP、Tool Calling 时，也会发现它们经常与 API 配合工作。

以 Web API 为例：

```
Client
    ↓
按照 API 规定发送 Request
    ↓
Server
    ↓
按照 API 约定返回 Response
```

举个具体的天气查询例子：

```
客户端发出请求：
GET https://api.example.com/weather?city=Shanghai

服务器按 API 规定的格式返回：
{
  "city": "Shanghai",
  "temperature": 28,
  "condition": "多云"
}
```

**API 不是服务器本身，也不是网络本身——API 是软件之间"怎么打交道"的约定**。客户端不需要知道服务器内部怎么算出结果的，只要照着约定的格式发请求，就能拿到约定好格式的答案。

### 核 / 并行 / GPU

**核（Core）**

处理器中能够相对独立执行一条指令流的计算核心。一个处理器内部可以有多个核，因此可以同时处理更多工作。（这里不深入 SMT、SIMD、warp、execution unit 这些细节，也不给具体数字——核的数量随硬件迭代变化很快，记住某个具体数字对建立心智模型没有帮助。）

**并行（Parallelism）**

把可以同时进行的工作分开，让多个计算单元同时处理，而不是全部排队依次完成——这些计算单元可以是同一个处理器里的多个核，也可以是多个处理器、甚至多台机器：

```
Sequential
A → B → C → D

Parallel
A ─┐
B ─┤
C ─┤ → 同时处理
D ─┘
```

AI 训练和推理中存在大量可以并行执行的数学计算，这也是 GPU 在 AI 里特别重要的原因（这里不展开矩阵运算的细节）。

**GPU（Graphics Processing Unit，图形处理器）**

CPU 通常拥有相对较少、但功能很强、很灵活的计算核心，擅长处理复杂、分支较多、顺序性较强的任务；GPU 拥有大量适合并行计算的执行资源，擅长同时进行大量结构相似的计算。

GPU 的优势不只是"核心数量更多"，而是它的整体架构本身就是为高吞吐量并行计算设计的——不是"CPU 只不过核更多"这么简单。细节见 [CPU vs GPU](cpu-vs-gpu.md)。（这里不展开 CUDA Core、Tensor Core、SIMD、SIMT、Warp、Matrix multiplication、FLOPS、Memory bandwidth，留给 Hardware Foundations。）

## 补充一个原子：Bit / Byte

这组概念不在上面"5 组原子"的心智图卡片里，但后面学 AI 时会频繁遇到 8-bit、4-bit、FP16、BF16、INT8、Model Size、Memory、Quantization 这些说法，如果完全不知道 bit / byte，这些概念会缺一个最底层的锚点，所以单独在这里补一段——只建立直觉，不教二进制运算。

**Bit（比特）**

计算机表示信息的最小单位，可以简单理解成一个 0 或 1——像一个只能开或关的小开关。

**Byte（字节）**

8 个 bit 组成一个 byte——像一小组这样的开关放在一起。

```
8 bits = 1 Byte

Byte
  ↓
KB
  ↓
MB
  ↓
GB
  ↓
TB
```

这一串单位描述的是"有多少数据"。这里不涉及 binary arithmetic（二进制运算）、hexadecimal（十六进制）、two's complement（补码）、IEEE 754，也不讨论 1024 vs 1000 的单位换算争议——这些都不属于 Zero 层。

## 把这一切连起来

分开看，上面的概念容易被记成互不相关的几个抽屉。放在一起看，它们其实是一个系统。

**第一张图：一个程序怎么被跑起来**

```
Program
存放在 Storage

    ↓ 运行时加载

Memory
    ↓
Process
    ↓
Operating System 管理资源
    ↓
CPU / GPU
    ↓
执行计算
```

**第二张图：一次请求怎么走完全程**

```
Client
   │
   │ Request
   ▼
Network
   │
   ▼
Server
   │
   │ 运行 Program / Process
   ▼
CPU / GPU
   │
   │ Response
   ▼
Network
   │
   ▼
Client
```

API 就放在 Request / Response 这一层旁边：它规定双方如何提出请求、传递信息、理解返回结果。

用一段话把所有概念串起来：一个程序通常存放在存储设备中；运行时，它被加载到内存，成为一个正在运行的进程，操作系统负责协调 CPU、GPU、内存和存储等资源。如果这个程序需要使用另一台机器或另一个程序提供的服务，它可以作为客户端通过网络发送请求；另一方作为服务器响应请求，双方通常按照 API 约定的规则通信。
