# FLOPS 与精度：为什么降精度能提速

**核心概念**: 上一篇 [CPU vs GPU](cpu-vs-gpu.md) 已经讲了 GPU 为什么靠"海量核心并行"赢过 CPU。这篇接着往下问：同一块 GPU，为什么把数字的精度调低，速度还能再快一截？原因不止一个——数字更小，同样宽的硬件能同时塞下更多；数字更小，搬运也更快；不少硬件还专门为低精度运算做了加速。

---

## FLOPS 是什么

**FLOPS**（Floating-point Operations Per Second，每秒浮点运算次数）是衡量"这块硬件一秒钟能做多少次数学运算"的单位——不是"这块芯片有多聪明"，纯粹是"手有多快"。

**最简单的心智图像**：FLOPS 像一条流水线一秒钟能装配多少个零件——流水线越宽（核心越多，见 [CPU vs GPU](cpu-vs-gpu.md)）、每个零件越小（数字精度越低），单位时间能装配的零件就越多。

## 精度是什么，为什么它能换速度

一个数字要占多少"位置"，取决于用几个 bit 去表示它——这就是**精度（Precision）**。同样一条比如说 256 bit 宽的计算通道：

```
如果每个数字用 32 bit 表示 → 一次能塞下  8 个数
如果每个数字用 16 bit 表示 → 一次能塞下 16 个数
如果每个数字用  8 bit 表示 → 一次能塞下 32 个数
```

**数字越"粗略"，硬件同一条通道里能同时塞下的数字就越多**——这是降精度能提速的一个原因，但不是唯一原因。降精度还从另外两个方向帮上忙：

1. **塞得下更多**（上面这条）：同样宽的计算通道，一次能同时处理更多数字。这跟 [CPU vs GPU](cpu-vs-gpu.md) 里"GPU 靠海量核心并行"是同一个逻辑的另一层——并行是"同时用多少个核心干活"，精度是"每个核心一次能处理多宽的数字"，两个维度都在把"同时能干的量"堆上去。
2. **搬得更快**：数字变小了，占的存储空间也变小，同样的内存带宽单位时间能搬运更多数字——"算得快"和"数据搬得快"其实是两件不完全一样的事，具体展开见 [内存墙：为什么很多时候不是算不动，而是数据送不到](memory-wall.md)。
3. **硬件专门为它优化过**：不少现代芯片（尤其是给深度学习设计的部分）对低精度运算本身配备了更快的专用计算路径，不只是"数字变小了顺便塞得下更多"，也包括硬件设计时就为低精度单独开了"快车道"。

这三条加在一起，才是"降精度能提速"背后更完整的原因——不是芯片突然变聪明了。

代价也在这——精度降低，数字表示得没那么精确，模型算出来的结果可能有一点点偏差。什么时候这点偏差可以接受、什么时候不行，是 [Quantization（量化）](../ai-research/models-deep-dive.md#技术-3量化quantization) 要回答的问题（那篇讲的是"精度换了多少准确率"，这篇讲的是"精度为什么能换速度"——两个不同的问题）。

## 常见的精度格式（认识就好）

FP32、FP16、BF16、INT8、INT4 是"精度"这个概念在实际硬件/框架里的具体名字——概念是"用几个 bit 表示一个数"，这些缩写只是具体的位数选择，不用死记每一种的细节：

| 格式 | 大致含义 |
|---|---|
| FP32 | 32 bit，训练时常见的"高精度"起点 |
| FP16 / BF16 | 16 bit，推理里很常见的折中 |
| INT8 | 8 bit 整数，更快更省 |
| INT4 | 4 bit，更快更省，位数比 INT8 更少 |

**位数越少不代表准确率一定掉得越多**——具体损失多少，取决于模型、任务和量化方法，没有一条"到 INT8/INT4 就开始明显变差"的通用门槛，实际效果要具体测。这也是为什么 [Models 深挖](../ai-research/models-deep-dive.md#技术-3量化quantization) 会把"8-bit 量化"和"更激进的量化"分开讨论，而不是套一个固定标准。

## 这篇不讲什么

- 不讲 IEEE 754 浮点数具体怎么编码——那是数字表示法的细节，不是理解"为什么能提速"所必需的
- 不讲精度切换在软件层面具体怎么实现（编译器/kernel 怎么支持不同精度）——那是软硬桥脊 Bridge Spine 的事
- 不讲量化对模型准确率的具体影响——那是 [Models 深挖](../ai-research/models-deep-dive.md#技术-3量化quantization) 已经写过的内容
