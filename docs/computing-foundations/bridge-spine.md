# 软硬桥脊 · Bridge Spine

**核心概念**: 硬件的算力要真正被用起来，中间隔着一整条软件栈——编译器、kernel 库、运行时，每一层都在做关键决策。峰值性能和实际性能之间的差距，很大一部分就在这里。CUDA 生态之所以是护城河，不是因为某一层做得好，而是硬件、软件、协同打磨三样东西积累了十几年。

## 01 — 硬件都到位了，为什么模型还没跑到预期的速度？

[算力脊](compute-spine.md) 最后一节说过：峰值 TFLOPS ≠ 实际性能。那节列了三个原因（等数据、等通信、等软件），但只点了方向，没有展开"等软件"到底是什么意思。

现在展开。

一块 GPU 标着几千 TFLOPS，是它在理想条件下的理论峰值。但真实模型运行时，**把"高层代码写的模型"变成"硬件真正执行的指令"，中间有一整条软件栈在做翻译和决策。** 这条栈做得好不好，直接决定了硬件能力有多少被真正用上。

就像一辆标着 300 km/h 的跑车——实际开多快，不只取决于发动机，还取决于路况、变速箱调校、和驾驶员怎么操控。

## 02 — 硬件和模型之间到底隔着什么？

[Software × Hardware Map](software-hardware-map.md) 已经画过这条路：模型代码 → 编译器 → 核心运算库 → 运行时 → 硬件执行。

这条脊要补充的是：**这不是一条简单的传送带，而是每一层都在做关键决策的多层栈。**

| 软件层 | 它在做什么 |
|--------|-----------|
| **编译器（Compiler）** | 把高层模型代码翻译成底层指令，同时做各种优化——选择哪些运算可以合并、用什么顺序执行 |
| **核心运算库（Kernel / Library）** | 为特定硬件、特定运算写到极致快的小程序块——比如 cuBLAS 里的矩阵乘法 kernel，是针对 NVIDIA GPU 手工调优的 |
| **运行时（Runtime）** | 程序运行期间动态调度资源：决定哪些计算先跑、怎么凑批、内存怎么分配 |

每一层做得好不好，都会影响硬件能力有多少被真正用上。

## 03 — 这些软件层在做什么决策？

[Software × Hardware Map](software-hardware-map.md) 已经认识过四个决策维度：Scheduling（调度）、Batching（批处理）、Precision（精度）、Memory management（内存管理）。那篇把它们挂在 Runtime 名下方便记忆，现在要升级：

**这四件事并不都攒到运行时才决定——它们分散在编译器、核心运算库、运行时好几层。**

- 有些决策在**编译期**就定好了——比如针对某种输入形状提前选好用哪个 kernel
- 有些藏在 **kernel 本身怎么写**里——一个 kernel 可能只为某种精度、某种批大小调优过
- 只有一部分是**运行时**动态决定的——比如根据当下请求量决定要不要凑一批

具体哪个决策落在哪一层，因系统而异，没有统一答案。这正是这条脊要讲的第一个道理：**软硬件之间不是"一处交接"，是层层交接。**

## 04 — 为什么 CUDA 是护城河？

理解了"决策分散在每一层"，就能理解 CUDA 护城河的真正含义。

CUDA 的护城河不是单靠硬件或单靠软件——是三样东西一起积累了十几年：

1. **硬件能力**——芯片本身的持续迭代
2. **软件生态**——cuDNN、cuBLAS 等高度优化的核心库，成熟的编译工具链，主流 ML 框架长期以来对 NVIDIA GPU 有非常成熟、广泛的优化支持
3. **协同设计（Hardware/Software Co-design）**——硬件怎么设计，参考真实工作负载和软件生态的反馈；软件怎么优化，针对这一代硬件的具体特性去调。两者互相反馈、一起打磨

为什么难替代？因为正是"决策分散在每一层"这件事意味着：**挑战者要同时接住每一层，不能只赢一层。** 新平台哪怕芯片本身很快，只要编译器成熟度或库的覆盖面跟不上，实际拿到的性能就会打折扣。

换一块硬件，就算硬件本身很有竞争力，也要重新走一遍"软件为这块硬件调优"的整个过程——这才是真正难替代的地方。

完整展开见 → [CUDA 护城河：为什么软硬之间的决策分散在每一层](cuda-moat.md)。

## 05 — 这对理解 AI 竞争有什么意义？

这条脊解释了 AI 硬件竞争中一个经常被忽略的维度：

**"新硬件跑分很漂亮"≠"马上能用"** —— 论文测出来的峰值性能和实际能拿到的性能之间，往往就隔着一个不成熟的软件栈。一块峰值 FLOPS 更低、但软件栈打磨了几年的老硬件，在实际部署中可能比新硬件更快。

**硬件公司不只是硬件公司** —— NVIDIA 的竞争力不是"晶体管设计得好"，而是整个 CUDA 生态让开发者不想离开。Google TPU 的竞争力也不只是芯片，是 XLA 编译器 + TPU 硬件的协同设计。AMD 追赶的难点不在芯片性能本身，在于 ROCm 软件生态的成熟度。

**Peak FLOPS 不是终点** —— 前三条脊教了"为什么峰值不等于实际"；这条脊补上了最后一块拼图：实际性能还取决于软件栈有多成熟。

---

到这里，四条脊的逻辑已经闭合：

```
算力（能算多快）→ 内存（数据搬得有多快）→ 规模（多台怎么一起快）→ 桥（软件怎么让硬件真正被用起来）
```

但所有这些脊都默认了一个前提：**硬件本身存在，而且能被制造出来。**

芯片从哪来？谁在造？造得出多少？这些物理层面的约束，又给 AI 的发展设了一道完全不同的门槛。

这就是第五条脊：**[半导体脊 · Semiconductor Spine](semiconductor-spine.md)**。
