# CPU vs GPU：为什么 GPU 赢了深度学习

**核心概念**: CPU 和 GPU 是针对不同工作负载做出的不同架构取舍——CPU 把更多芯片资源投入复杂控制，强调通用性和低延迟；GPU 把更多资源投入大规模并行算术，强调吞吐量。现代神经网络的大量计算恰好具有高度并行、运算规整的特点，正好落在 GPU 的设计甜区里。

⚠️ **升级 Foundation Zero 的近似**：[Foundation Zero](foundation-zero.md) 用"一个厨师 → 一排同时炒 → 上千人的配菜流水线"来入门理解"核 / 并行 / GPU"。这个比喻帮助建立了"很多计算可以同时做"的直觉，但需要升级：GPU 不是"很多个跟 CPU 一样的厨师"，而是一种从头到尾为不同目标设计的架构。

---

## 两种不同的设计取舍

### CPU：为复杂、低延迟设计

CPU 把大量芯片面积花在复杂控制上：分支预测、乱序执行、多级缓存、复杂的控制逻辑。这些电路的目的是让"这一个任务"尽快跑完，哪怕任务里全是分支判断、依赖前一步结果、类型各异。

一个直觉：在一颗典型的 CPU 芯片上，**真正做运算的 ALU（算术逻辑单元）只占芯片面积的一小部分**，大量面积被分支预测器、乱序执行引擎、多级缓存这些"让一条复杂指令流跑得更快"的电路占掉了。这不是浪费——这是通用计算的代价：操作系统调度、数据库查询、网页服务器，都是"控制流复杂、单个任务要快"的场景。

### GPU：为简单、高吞吐设计

GPU 的设计取舍恰好反过来：把分支预测、乱序执行这类复杂控制的芯片面积压到最小，省下来的面积换成大量并行计算资源。

GPU 的假设是：如果同一种运算要在大量数据上重复执行，那么比起"少数几个功能强大的核"，更划算的是"海量并行计算资源一起干"。

### 关于核心数量的一个重要说明

你经常会看到"CPU 有几十到上百个核，GPU 有上万个 CUDA 核心"这样的数字对比。这个对比帮助感受两种架构在资源分配上的巨大差异，但必须明确：**CPU core 和 CUDA core 不是同一种粒度的计算单位，不能一一相比**——一个 CPU core 包含的硬件复杂度远高于一个 CUDA core。数字只说明一件事：两种架构把芯片资源花在了不同的地方。

## GPU 怎样并行：SIMT

GPU 不是让每个计算单元各自独立做自己的事——那样调度开销太大。NVIDIA GPU 采用一种叫 **SIMT（Single Instruction, Multiple Threads）** 的执行模式：几十个线程编成一组（NVIDIA 叫 **warp**，一个 warp 通常 32 个线程），同一个 warp 里的线程在同一时刻执行**同一条指令**，只是各自处理不同的数据。

这意味着 GPU 天然适合"所有人做同一件事、只是数据不同"的工作模式。反过来，如果一段代码里有很多 if/else 分支，同一个 warp 里的线程走了不同的分支路径，GPU 不得不让没走这条路径的线程干等着（这叫 **warp divergence**），吞吐量会大打折扣。

一句话：**GPU 快的前提是"大家做同一件事"——分支越多，优势越小。**

## 为什么矩阵乘法和张量运算特别适合 GPU

现代神经网络的大量计算最终会被组织成矩阵乘法及相关张量运算。一个大语言模型做一次前向传播，核心工作就是一连串矩阵乘法——参数量越大、输入越长，矩阵越大、计算量越多。

这些运算恰好满足 GPU 最擅长的三个条件：

1. **高度并行**：结果矩阵的每个元素可以独立计算，不依赖其他元素的结果
2. **运算规整**：每个元素都是"一行 × 一列，乘完累加"，同一种运算重复做——完美符合 SIMT"同一条指令、不同数据"的模式
3. **数据可复用**：矩阵 A 的一行会被用来跟 B 的每一列配对，搬一次数据可以复用多次——这就是 [内存墙](memory-wall.md) 里"算术强度高"的含义

## 从通用到并行到专用：Tensor Core

GPU 靠大量并行计算资源赢了深度学习。但硬件演化并没有停在"更多并行"这一步——它还走了一步：**为关键 workload 做专用硬件**。

```
General-purpose compute（CPU：通用计算）
        ↓
Parallel compute（GPU：大规模并行计算）
        ↓
Specialized compute（Tensor Core：为矩阵运算设计的专用执行单元）
```

从 2017 年的 Volta 架构开始，NVIDIA 在 GPU 里加入了 **Tensor Core**——专门为矩阵乘加运算（D = A × B + C）设计的执行单元。普通的 CUDA 核心一次做一个标量的乘加（a × b + c）；Tensor Core 一次做一小块矩阵的乘加——同一个时钟周期里完成的有效运算量高得多。

| | CUDA 核心 | Tensor Core |
|---|---|---|
| 一次做什么 | 一个标量的乘加 | 一小块矩阵的乘加 |
| 通用性 | 什么运算都能做 | 专为矩阵乘法设计 |
| 在深度学习里的角色 | 通用计算 | 矩阵运算的主力 |

Tensor Core 在这条脊里真正承担的教学作用是：**现代 AI 硬件不仅通过"更多并行"提高性能，还通过"为关键 workload 做专用硬件"进一步提高效率。** 这也为 [半导体脊](semiconductor-spine.md) 埋下伏笔——芯片设计越来越专用化，对制造工艺的要求也越来越高。

## 对比总结

| | CPU | GPU |
|---|---|---|
| 设计取舍 | 芯片面积花在复杂控制，让单个任务快 | 芯片面积花在并行计算资源，让同一运算在大量数据上并行 |
| 擅长 | 分支多、依赖复杂的通用任务 | 同一运算在大量数据上重复执行（矩阵乘法、张量运算） |
| 不擅长 | 海量简单运算并行 | 分支密集的代码（warp divergence） |
| 执行模式 | 每个核独立执行不同指令流 | 一个 warp（32 线程）同时执行同一条指令（SIMT） |
| 专用化 | 通用 | 进一步加入 Tensor Core 等专用执行单元 |

## 比喻在哪里升级

Foundation Zero 的"上千人的配菜流水线"帮助建立了"很多计算同时做"的直觉。读完这篇，这个直觉需要升级三件事：

1. **架构取舍不同**：GPU 不是"很多个缩小版 CPU"——两种架构从设计目标开始就不同
2. **执行方式不同**：不是每个计算单元独立做自己的事，而是一组线程同步执行同一条指令（SIMT）
3. **还有专用硬件**：Tensor Core 不是"更多的通用核心"，而是专为矩阵运算设计的电路
