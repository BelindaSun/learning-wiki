# CPU vs GPU：为什么 GPU 赢了深度学习

**核心概念**: GPU 不是"核更多的 CPU"。两者是两种不同的设计取舍——CPU 把芯片面积花在复杂控制、分支预测、低延迟上；GPU 把面积花在数量庞大但相对精简的核心上，专为高吞吐并行而生。深度学习恰好是"同一种简单运算重复做几十亿次"，正好踩中 GPU 的设计甜区。

⚠️ **纠正 Foundation Zero 的近似**：[Foundation Zero](foundation-zero.md) 用"一个厨师 → 一排同时炒 → 中央厨房"来入门理解"核 / 并行 / GPU"，这个比喻在这里要升级：中央厨房听起来像"同一个厨师的能力，简单复制几千份"，但 GPU 和 CPU 的核，本身设计目标就不一样，不是同一种"厨师"的数量差异。

---

## CPU：为复杂、低延迟设计

CPU 通常只有几个到几十个核（服务器级别的 CPU 做到 64–192 核已经算很多了），但每个核都很"重"：分支预测、乱序执行、多级缓存、复杂的控制逻辑——这些电路的唯一目的，是让"这一个任务"尽快跑完，哪怕任务里全是分支判断、依赖前一步结果、类型各异。

一个直觉：在一颗典型的 CPU 芯片上，**真正做运算的 ALU（算术逻辑单元）只占芯片面积的一小部分**，大量面积被分支预测器、乱序执行引擎、多级缓存这些"让一条复杂指令流跑得更快"的电路占掉了。这不是浪费——这是通用计算的代价：操作系统调度、数据库查询、网页服务器，都是"控制流复杂、单个任务要快"的场景，需要这些电路来应对。

## GPU：为简单、高吞吐设计

GPU 的设计取舍恰好反过来：把分支预测、乱序执行这类复杂控制的芯片面积压到最小，省下来的面积全换成计算核心。NVIDIA 目前用于 AI 的旗舰芯片（H100）有约 **16,896 个 CUDA 核心**——相比服务器 CPU 的几十到上百核，差了两个数量级。

GPU 的假设是：如果同一条指令要在几万个数据上重复执行（比如给一张图片的每个像素上色，或者给一个矩阵的每个元素做乘法），那么比起"少数几个非常聪明的核"，更划算的是"海量相对精简的核一起干"。

### SIMT：GPU 并行的实际方式

GPU 不是让每个核各自独立想干什么就干什么——那样调度开销太大。NVIDIA GPU 采用一种叫 **SIMT（Single Instruction, Multiple Threads）** 的执行模式：几十个线程编成一组（NVIDIA 叫 **warp**，一个 warp 通常 32 个线程），同一个 warp 里的线程在同一时刻执行**同一条指令**，只是各自处理不同的数据。

这正是为什么 GPU 天生适合矩阵乘法：矩阵乘法的每个元素都在做同一种"乘法+累加"运算，只是输入数据不同——完美符合 SIMT"同一条指令、不同数据"的执行模式。反过来，如果一段代码里有很多 if/else 分支，同一个 warp 里的线程走了不同的分支路径，GPU 不得不让没走这条路径的线程"干等着"（这叫 **warp divergence**），吞吐量会大打折扣。

一句话：**GPU 快的前提是"大家做同一件事"——分支越多，优势越小**。

## 为什么矩阵乘法是关键运算

深度学习为什么离不开矩阵乘法？不是因为谁规定了必须用矩阵——是因为神经网络的核心操作（一层的输出 = 权重矩阵 × 输入向量 + 偏置）本身就是矩阵运算。一个大语言模型做一次前向传播，本质上就是一连串矩阵乘法，参数量越大、输入越长，矩阵就越大。

矩阵乘法恰好满足 GPU 最喜欢的三个条件：

1. **高度并行**：矩阵 C 的每个元素可以独立计算，不依赖其他元素的结果
2. **运算规整**：每个元素都是"一行 × 一列，乘完累加"，同一种运算重复做
3. **数据可复用**：矩阵 A 的一行会被用来跟 B 的每一列配对，搬一次数据可以复用多次（这就是 [内存墙](memory-wall.md) 讲的"算术强度高"）

这三条合在一起，就是为什么 GPU + 矩阵乘法是一对天然的搭配。

## Tensor Core：专门为矩阵乘法造的硬件

CUDA 核心已经很擅长矩阵乘法了，但从 2017 年的 Volta 架构开始，NVIDIA 在 GPU 里加了一种更专用的计算单元——**Tensor Core**。

CUDA 核心一次做一个标量的乘加运算（一次 a × b + c）；Tensor Core 一次做**一小块矩阵的乘加运算**（比如一次算完一个 4×4 矩阵乘法的结果）——同一个时钟周期里完成的有效运算量，比用 CUDA 核心拆成一个个标量来做要高得多。

| | CUDA 核心 | Tensor Core |
|---|---|---|
| 一次做什么 | 一个标量的乘加（a × b + c） | 一小块矩阵的乘加（D = A × B + C） |
| 通用性 | 什么运算都能做 | 专为矩阵乘法设计 |
| 在深度学习里的角色 | 通用计算，也能做矩阵乘法 | 矩阵乘法的主力 |

H100 上，用 Tensor Core 做 FP16 矩阵乘法的峰值吞吐量大约是 **990 TFLOPS**——是同一块芯片用 CUDA 核心做 FP32 的 **~15 倍**。这个差距不只是精度不同造成的（精度的故事见 [FLOPS 与精度](flops-and-precision.md)），也包括 Tensor Core 本身"一次算一块矩阵"带来的效率提升。

这也是为什么同一块 GPU 上，不同的运算类型实际能拿到的算力差距巨大——厂商宣传的峰值 FLOPS 通常是 Tensor Core + 低精度的数字，通用计算的实际吞吐量要低得多。

## 一句话对比

| | CPU | GPU |
|---|---|---|
| 设计取舍 | 芯片面积花在复杂控制，让单个任务快 | 芯片面积花在核心数量，让同一运算在海量数据上并行 |
| 核心数量 | 几十到上百个"重"核 | 上万个"轻"核 + 数百个专用 Tensor Core |
| 执行模式 | 每个核独立执行不同指令流 | 一个 warp（32 线程）同时执行同一条指令（SIMT） |
| 擅长 | 分支多、依赖复杂的通用任务 | 同一运算在大量数据上重复执行（矩阵乘法） |
| 不擅长 | 海量简单运算并行（核太少） | 分支密集的代码（warp divergence） |

## 比喻在哪里失效

"中央厨房"这个比喻暗示 GPU = 很多个"和 CPU 一样的厨师"，只是数量更多。真实情况是：

1. **核心本身不同**：GPU 核心被设计得更精简——把面积让给了数量，换来了吞吐量
2. **执行方式不同**：不是每个核独立做自己的事，而是 32 个线程一组，做同一件事（SIMT）
3. **还有专用硬件**：Tensor Core 不是"更多的通用核"，而是专门为矩阵乘法设计的电路

不是"人数变多"，是"组织方式和每个人的能力都变了"。
