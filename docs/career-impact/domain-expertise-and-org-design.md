# AI Agent 时代的 Domain Expertise 重估与组织变革

**核心概念**: Agent 正在把"会执行"变成商品，把"懂判断"变成稀缺资源，而大多数组织还没意识到个人提效 ≠ 组织提效这道鸿沟。传统的 know-what / know-how / know-why 正在贬值，真正增值的是"知道什么值得做、什么算做好了、什么时候会出问题"这些无法言语化、因此也很难被 Agent 学走的高阶判断力。

**学习来源**: OpenAI "How agents are transforming work" + Anthropic "Agentic coding and persistent returns to expertise"

## 一句话总结

Agent 正在把"会执行"变成商品，把"懂判断"变成稀缺资源，而大多数组织还没意识到个人提效 ≠ 组织提效这道鸿沟。

---

## 今天最大的收获

Domain expertise 的价值排序需要彻底重写。传统的 know-what / know-how / know-why 正在贬值，真正增值的是 know-what-matters（知道什么值得做）、know-what-good-looks-like（质量判断力）、know-what-can-go-wrong（风险直觉）这些无法言语化、因此也很难被 Agent 学走的高阶能力。而且门槛效应非常明显——不需要精通，但必须跨过 competent 这条线。

---

## 原来我认为…… vs 现在我认为……

**原来认为**: AI 对新手帮助更大，因为它补短板。

**现在认为**: AI 对所有人都有帮助，但对有 domain expertise 的人帮助是倍数级的——因为 Agent 的工作模式是**委托**而非**教学**，你给出的约束越精准，Agent 能跑的距离越远。Karpathy 们撬动的不是更好的 prompt，而是更好的工作流设计。

一个类比：新手走进建筑事务所说"帮我盖个房子"，施工队只能靠猜；资深建筑师说"三层钢混框架，地基按 8 度抗震做，北面开窗比控制在 25% 以内"，施工队拿到的是可以直接执行的指令集，而且一旦走偏，建筑师能第一时间发现并纠正。Anthropic 的数据印证了这个比喻：专家给出的指令密度是新手的两倍多（每条 prompt 触发 12 vs 5 个动作），输出量是五倍（3200 vs 600 words）——不是因为专家打字更多，而是他们的指令包含了足够的约束和上下文。

## 最重要的三个知识点

### 1. 人管 planning，Agent 管 execution

这是当前 agentic 协作的基本分工结构。Anthropic 数据：人做 70% 的 planning 决策，Claude 做 80% 的 execution 决策。**成功率取决于你能否做好那 70%，而非能否替代那 80%。**

新手放弃率是其他人的 3-4 倍，不是因为没耐心，而是缺乏判断力——Agent 输出一堆东西，新手分不清哪些是正确的、哪些是胡说，最终只能放弃。专家能在错误刚冒头的时候就介入纠偏。

一个重要信号：中级和专家之间的差距其实不大，大部分收益集中在从新手到中级的跃迁。门槛不是精通，而是 **competence**——低于这个门槛，Agent 对你几乎不可用；一旦跨过，继续精进的边际收益会明显放缓。

### 2. 个人生产力 ≠ 组织生产力

中间隔着流程瓶颈、信息过载、激励错位和旧架构惯性。每个员工都觉得自己快了，但公司总产出没变——因为大多数公司在用 AI **加速旧流程**，而不是**重新设计流程**。

四个具体原因：
- **个人提效在组织层面互相抵消**：市场部一周产出原来一个月的内容量，但法务审核速度没变，结果更多内容卡在审核流程里——局部优化不等于全局优化，甚至可能恶化全局
- **产出增加不等于价值增加**：分析师一天能写五份报告，但决策者的注意力还是只够消化一份，多出来的四份制造了噪音，增加了筛选成本
- **流程和激励结构还停留在前 AI 时代**：一个人加 Agent 一天能完成一周的工作量，但还是得等周一例会汇报、等审批链签字、等下个 sprint 排期
- **大多数公司在用 AI 加速旧流程，而非重新设计流程**：很多现有流程的存在理由是"人的产能有限"（因为一个人一天只能审 10 份合同，所以需要 5 个人的法务团队）；当这个约束消失，流程本身就该被重新设计，而不是在旧流程上贴 AI 加速补丁

管理者真正要做的三件事：**识别真正的瓶颈**（通常是决策速度、审批流程、跨部门协调，而不是个人产出速度）、**重新设计工作流而不是加速旧工作流**、**重新定义什么叫"产出"**（当每个人都能产出更多，组织的稀缺资源就变成了判断力和注意力，而非产出能力本身）。

### 3. "管理 Agent"正在分化为四层能力

Boris 砍掉 80% 的 prompt 反而效果更好，说明"少管"和"不管"之间有一条精细的线，这条线本身就是一种新的专业能力：

1. **任务委派能力**——知道什么该交给 Agent、什么不该，一个任务该拆成几块、先后顺序是什么、哪些可以并行（顶级用户一天并行跑出 60+ 小时的 Agent 工作量，这需要任务编排的直觉，不是随便丢任务就能做到）
2. **质量判断能力**——Agent 交回来的东西，能不能在 30 秒内判断"方向对了"还是"完全跑偏了"（新手放弃率高的根本原因就在这里）
3. **系统设计能力**——不是管一个 Agent，而是设计一个 Agent 系统：什么工具给它用、什么权限开放、什么边界设定、什么检查点放在哪里
4. **知道什么时候不要管**——过度介入和放任不管一样有害，好的 Agent 管理者知道在哪里设护栏，然后在护栏之内完全放手

早期 Agent 需要详细 prompt 是因为能力不够，需要手把手带；现在 Agent 自己能做更多判断了，过度指令反而成了噪音、干扰推理——就像团队成员越成熟，越微管理越做不好。"管理 Agent"更精确的定位不是一种独立的新职业，而是**正在成为所有职业能力的底层基础设施**，就像"会用电脑"在 2000 年代从专业技能变成了所有职业的前提条件——只是这次门槛更高，因为它要求你在自己的领域有真正的判断力，而不只是会按按钮。

## Domain Expertise 的完整重排框架

传统上专业知识分三层：know-what（事实概念）、know-how（操作流程）、know-why（原理因果）。这个框架在 AI 时代不够用了，因为这三层恰好是 AI 最容易替代的部分。

**正在被 Agent 快速吞噬的三层**：
- **Know-what**——事实、数据、规则、条款。Agent 的检索能力远超人类记忆，几乎没有价值了
- **Know-how**——具体怎么操作（怎么写 SQL、怎么起草合同）。Agent 已经拿走了 80% 的 execution 决策
- **Know-why**——为什么这样做、底层原理是什么。比前两层更耐久，但也在被侵蚀

**真正在增值的七层**：

| 层级 | 定义 | 为什么难被 Agent 替代 |
|------|------|------|
| Know-what-matters | 问题识别与优先级判断——知道什么值得做 | 来自多年浸泡领域形成的模式识别，不是任何 prompt 能替代的 |
| Know-what-good-looks-like | 质量判断力——能不能一眼判断"够好了"还是"差得远" | 是一种审美和深度内化，几乎无法言语化 |
| Know-what-to-ask | 提问能力——知道哪些是关键未知、哪些假设需要被挑战 | 专家的 prompt 不是更长，而是约束条件更精准 |
| Know-what-can-go-wrong | 风险直觉——对"哪里可能出事"的直觉性预判 | Agent 能做基于已知框架的系统性风险分析，但人的直觉覆盖框架之外、来自痛苦经验的模式 |
| Know-when | 时机判断与决策勇气——什么时候行动、等待、放弃 | 不是分析能力，是在不确定性下做决策的能力；"够好就行"的务实判断需要对真实世界摩擦的深度理解 |
| Know-who | 关系网络与信任资本——谁能帮你、谁的判断可信 | 当每个人都能借助 Agent 产出大量内容，辨别"谁说的话值得听"反而更重要 |
| Know-how-to-orchestrate | 统筹管理——综合运用以上所有能力，同时管理多个 Agent | 需要在关键节点问对问题、快速判断输出质量、预判风险、拍板决策 |

重排后的价值排序：
```
know-what-matters > know-what-good-looks-like > know-what-can-go-wrong
  > know-when > know-what-to-ask > know-who > know-how-to-orchestrate
  > know-why > know-how > know-what
```

前七项在增值，后三项在贬值——而传统教育和职业培训几乎全部集中在后三项上。

## 如果一个人能同时管理 10 个 Agent，组织结构会怎样变？

这不是在问技术，是在问权力结构的重组。今天一个中层经理管 8-12 个人，工作是协调、分配、审核、汇报；如果一个人能管 10 个 Agent、每个 Agent 产出相当于一个初中级员工，他一个人就是一个部门。

四条展开的线索：

1. **中间层会被大幅压缩**——传统中间管理层的核心价值是"翻译"（把战略翻译成可执行任务、把执行结果汇总上报），Agent 同时取代了这两个方向的摩擦，"翻译官"的价值急剧缩水
2. **组织基本单元从"团队"变成"个人 + Agent 集群"**——公司不再是部门组成的金字塔，更像一个个高度自治节点组成的网络
3. **"管理"这个词会分裂成两种领导角色**——管人需要情商、激励、政治敏感度；管 Agent 需要系统设计、质量判断、任务编排，少数两者兼备的人会最有价值
4. **公司边界会变模糊，招聘逻辑会反转**——现在按职能招人（前端工程师、数据分析师），未来可能按问题域招人（深刻理解支付合规的人），至于用什么 Agent、怎么组织工作流是他自己的事；成功率取决于 domain expertise，不取决于职业标签
